I log sono di due tipi: quelli del server, nella pagina **Log**, e quelli di ogni sito, nella sua
scheda **Log**. Il pannello mostra le ultime righe; premi **Aggiorna** per rileggerle.

## I log del server {#server-logs}

Apri **Log** dal menu. Le schede sono:

| Scheda | Cosa contiene | Dove si trova |
| --- | --- | --- |
| **Nginx access** | Il log generale degli accessi di nginx. | `/var/log/nginx/access.log` |
| **Nginx error** | Gli errori di nginx. | `/var/log/nginx/error.log` |
| **PHP-FPM** | Il journal dei processi PHP di tutti i siti. | journal, `cloudground-php-*.service` |
| **MariaDB** | Gli errori del database. | `/var/log/mysql/error.log` |
| **API** | Il pannello. | journal, `cloudground-api.service` |
| **Agent** | L'agente che fa le operazioni da root. | journal, `cloudground-agent.service` |

Gli operatori non vedono questa pagina: i log del server riguardano tutti i siti.

## I log di un sito {#site-logs}

Apri il sito e vai alla scheda **Log**. Le schede sono **Accessi**, **Errori** ed **Errori PHP**, con
le ultime 200 righe. Sul disco sono in `/var/log/cloudground/<dominio>/`:

| Scheda | File |
| --- | --- |
| **Accessi** | `access.log` |
| **Errori** | `error.log` |
| **Errori PHP** | `php-error.log` |

Un file che non esiste ancora appare come *(log is empty or not created yet)*.

## Scarica i log interi di un sito {#download}

Il pannello mostra solo le ultime righe. Per l'intero file, apri la scheda **Log** del sito e guarda il
riquadro **Scarica i log**: elenca i log di accesso e di errore, quello attuale (`access.log`,
`error.log`) e quelli ruotati (`access.log.1`, `access.log.2.gz`, …), con dimensione e data dell'ultima
scrittura. Premi **Scarica** accanto al file che ti serve.

- I log ruotati più vecchi di un giorno sono compressi (`.gz`): si scaricano così come sono e si
  aprono con `gunzip` o `zcat`. Ne restano 14 giorni.
- Il log attuale viene inviato com'è in quel momento, mentre nginx continua a scriverci: la dimensione
  mostrata è solo orientativa, e se una rotazione lo svuota durante il download il file finisce lì. I
  log ruotati non cambiano.
- Il riquadro c'è solo per gli amministratori e per gli operatori assegnati al sito, non per gli account
  in sola lettura. Ogni download è registrato nel registro di audit (`site.logs.download`).
- Si scaricano solo i log di accesso e di errore del sito: non `php-error.log`, né altri file della
  cartella.

Dalla riga di comando:

```bash prompt
cgctl logs <id-del-sito>
cgctl logs <id-del-sito> access.log.2.gz
cgctl logs <id-del-sito> error.log -        # sullo standard output
```

Il secondo comando scrive `access.log.2.gz` nella cartella corrente (o nel file indicato come terzo
argomento) e non sovrascrive un file che esiste. Funziona con file di qualsiasi dimensione.

## Dal server {#on-the-server}

Come root, i log nel journal si leggono con `journalctl`:

```bash prompt
journalctl -u cloudground-api -u cloudground-agent -n 100
```

## Dall'API {#from-the-api}

`GET /api/logs?source=<sorgente>&lines=<n>` legge un log del server; `source` è `nginx-access`,
`nginx-error`, `php-error`, `mariadb`, `api` o `agent`, e `lines` va da 1 a 2000 (200 se manca).
`GET /api/sites/<id>/logs?source=<tipo>` legge un log del sito; `source` è `access`, `error` o `php`.
Una riga più lunga di 8 KiB viene tagliata. `GET /api/sites/<id>/logs/files` elenca i log scaricabili e
`GET /api/sites/<id>/logs/download?file=<nome>` scarica un file intero, per gli account che gestiscono il sito.
