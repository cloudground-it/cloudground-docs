In questo tutorial installi CloudGround su un server nuovo e crei l'account amministratore. Alla
fine apri il pannello nel browser.

:::warning[Usa un server dedicato]

L'installer prende in mano nginx, PHP, MariaDB e la configurazione di SSH. Installalo solo su un
server nuovo, o su uno che puoi ricreare.

:::

## Lancia l'installer {#run-the-installer}

Entra nel server come root:

```bash
ssh root@<ip-del-server>
```

`<ip-del-server>` è l'indirizzo pubblico del server. Poi lancia l'installer:

```bash prompt
curl -fsSL https://cloudground-it.github.io/cloudground/install.sh | bash
```

:::note[L'indirizzo dell'installer]

Oggi l'installer si scarica da `https://cloudground-it.github.io/cloudground/install.sh`. Quando il
dominio sarà collegato, lo stesso script risponderà anche a `https://get.cloudground.it`; quell'indirizzo
per ora non funziona.

:::

Lo script installa CloudGround v0.1.0. Scarica la release da GitHub, lancia il suo `cgctl` solo se
ha lo SHA-256 che lo script indica, e `cgctl` non installa nulla il cui manifesto firmato non si
verifica. Per controllare lo script stesso prima di lanciarlo, vedi
[verifica l'installer](/docs/server/verify-the-installer).

Prima controlla la macchina, poi mostra nove passi, ognuno con la sua durata (qui sotto senza i
tempi, che dipendono dal server):

```text
  ✓   1/9  Installing nginx, PHP, MariaDB, restic
  ✓   2/9  Creating users, directories and secrets
  ✓   3/9  Installing CloudGround binaries
  ✓   4/9  Tuning kernel and nginx workers
  ✓   5/9  Configuring nginx
  ✓   6/9  Tuning MariaDB
  ✓   7/9  Starting services
  ✓   8/9  Opening the firewall
  ✓   9/9  Log rotation and certificate renewal
```

Se il controllo della macchina trova dei problemi (sistema, architettura, memoria, disco, porte
occupate), li elenca tutti insieme e si ferma senza toccare nulla. Correggili e rilancia lo stesso
comando.

## Apri il link di setup {#open-the-setup-link}

Alla fine l'installer stampa un indirizzo come questo:

```text
  ✓  CloudGround is running

     Open   https://<ip-del-server>:8443/setup/<token>

     The link is valid for 24 hours and works once.
     Your browser will warn about the certificate — it is self-signed
     until you issue a real one. That is expected on first boot.
```

Se il firewall del server (ufw) è spento, seguono altre due righe: l'installer non lo accende, stampa
i comandi che lo accenderebbero con SSH, i siti e il pannello aperti. Per ora lasciali stare; la
pagina [firewall](/docs/access/firewall#enable) li spiega.

Apri il link nel browser. Il browser avvisa che il certificato non è valido: è autofirmato, ed è
normale al primo avvio. Accetta l'avviso per questo indirizzo.

## Crea l'account amministratore {#create-the-administrator}

La pagina **Primo accesso** chiede email e password.

1. **Nome** e **Cognome** sono facoltativi.
1. Scrivi la tua email.
1. Scegli una password di almeno 12 caratteri e ripetila in **Conferma password**.
1. Premi **Crea account**.

Il pannello crea il primo amministratore e ti fa entrare. Vedi la dashboard, ancora senza siti.

## Controlla che tutto giri {#check-it-runs}

Sul server, controlla i due servizi del pannello:

```bash prompt
systemctl is-active cloudground-agent cloudground-api
```

Entrambe le righe dicono `active`.
