Le stesse regole valgono nella finestra **Nuovo sito**, nella scheda **Database** del sito, in cgctl e
nell'API. Il pannello le controlla mentre scrivi; il server le controlla di nuovo.

## Nomi {#names}

Il nome di un database e il nome di un utente database seguono una sola regola:

| Regola | Valore |
| --- | --- |
| Forma | `^[a-z][a-z0-9_]{2,47}$` |
| Lunghezza | da 3 a 48 caratteri |
| Caratteri | lettere minuscole `a`–`z`, cifre, `_` |
| Primo carattere | una lettera |

Questi nomi sono riservati e rifiutati:

| Tipo | Nomi |
| --- | --- |
| Nomi | `mysql`, `sys`, `performance_schema`, `information_schema`, `root`, `debian_sys_maint`, `mariadb_sys`, `mysql_sys`, `mariadb`, `mysqld`, `admin`, `test`, `phpmyadmin`, `cloudground`, `replication`, `repl`, `monitor`, `backup` |
| Prefissi | `cg` seguito da una lettera e da `_` (per esempio `cgq_`: gli account e i database temporanei del pannello), `mysql_`, `sys_`, `mariadb_`, `test_` |
| La forma predefinita del pannello | `site_<n>`: ce l'ha solo il sito numero `<n>`, e solo quando la sceglie il pannello (sotto) |

Un nome è unico sul server:

- un nome di database che un sito ha già viene rifiutato (la finestra **Nuovo sito** dice
  *`<name>` è già usato su questo server*);
- un nome di utente che un sito ha già viene rifiutato allo stesso modo;
- database e utenti sono due elenchi separati, quindi un utente può chiamarsi come un database
  (l'utente principale spesso lo fa);
- un database o un utente creato fuori dal pannello non viene mai preso in carico: il suo nome è
  rifiutato.

## I nomi che sceglie il pannello {#defaults}

| Dove | Nome del database | Nome dell'utente |
| --- | --- | --- |
| Finestra **Nuovo sito** | proposto dal dominio: le sue parti senza l'ultima, unite da `_` (`blog.example.com` → `blog_example`); puoi cambiarlo | uguale a quello del database, finché non lo cambi |
| cgctl e l'API, senza un nome | `site_<id>` | `site_<id>` |

`<id>` è il numero del sito. Un nome proposto che sarebbe riservato riceve `site_` davanti
(`test.example` → `site_test`).

## Password {#passwords}

| Regola | Valore |
| --- | --- |
| Lunghezza | da 12 a 256 caratteri |
| Caratteri rifiutati | `'`, `"`, `\` e i caratteri di controllo |
| Spazi | nessuno all'inizio o alla fine |
| Lasciata vuota | il pannello ne genera una: 32 caratteri sicuri per gli URL |

La finestra **Nuovo sito** riempie il campo con una password generata di 24 caratteri sicuri per gli
URL, che puoi tenere o sostituire.

Perché quei tre caratteri: wp-cli scrive la password dell'utente principale in `wp-config.php` e non
mette correttamente tra virgolette `'`, `"` e `\`. Una password con uno di essi farebbe usare a
WordPress una password diversa, o romperebbe `wp-config.php`. Gli spazi alle estremità, perché una
password copiata li perde facilmente.

Una password si vede solo quando l'ha generata il pannello, e una sola volta: nel riepilogo del sito
nuovo, oppure subito dopo che crei un utente o ne reimposti la password. Il pannello non la mostra mai
più; ne imposti una nuova dalla scheda **Database**.

## Privilegi {#privileges}

| Nel pannello | Concesso sul database |
| --- | --- |
| **Nessuno** | niente |
| **Sola lettura** | `SELECT, SHOW VIEW` |
| **Tutti i privilegi** | `ALL PRIVILEGES` |

Ogni utente è `<nome>@localhost`: accede solo da questo server, con al massimo 50 connessioni alla
volta.
