Il pannello per un server Ubuntu che misura i suoi siti

Un comando installa CloudGround. Ogni sito nasce in cache, dimensionato sulla macchina, isolato dagli altri e con i backup fuori dal server. Le misure sono pubblicate, con il metodo.

Su un server nuovo, come root:

$ curl -fsSL https://get.cloudground.it | sudo bash

Ubuntu 24.04 o 26.04 LTS, amd64, almeno 1 GB di RAM, porte 80 e 443 libere.

Prove di sicurezza

Ogni garanzia del pannello ha un controllo che la verifica. Per ognuna: come si prova, e cosa succede quando la prova non passa.

Performance Guard

Prima di ogni Safe Push dallo staging

Metodo

Coppie di richieste alle stesse pagine di staging e produzione, tempo misurato sul server. Si calcolano la mediana della differenza e il suo intervallo al 95%.

Esito

Un rilascio più lento della produzione non viene pubblicato. Verdetti: OK, attenzione, bloccato, non concludente.

Ripristino di prova

Dopo ogni backup restic

Metodo

Ogni snapshot, cifrato e deduplicato fuori dal server, viene ripristinato a parte e controllato. Il tempo di ripristino è misurato, non stimato.

Esito

Un backup conta solo dopo che il ripristino di prova è riuscito. L'ultimo verificato non viene mai rimosso.

Isolamento

Per ogni sito, alla creazione

Metodo

Un utente Unix, un master PHP-FPM, una sandbox systemd e un account del database per sito. SFTP chiuso nella cartella del sito.

Esito

Un sito compromesso non vede i file né il database degli altri.

Deriva della configurazione

Sui file che il pannello gestisce

Metodo

Il pannello confronta i file gestiti con quelli che ha scritto. Se qualcuno li cambia a mano, lo segnala.

Esito

Non sovrascrive nulla da solo: scegli tu se ripristinare o mantenere la modifica.

Limiti di questa prova

Un rapporto di prova dice anche cosa non copre.

Pre-release

La v0.2.0 è rilasciata, la v0.3.0 è in uscita. Le interfacce possono cambiare prima della 1.0.

Nessun audit esterno

Il codice ha avuto una revisione di sicurezza interna. Nessuna società esterna l'ha ancora controllato.

Una macchina sola

Le misure valgono per un VPS da 2 vCPU. Il metodo è pubblico: rifallo sul tuo server.

Codice consultabile, non open source

Procedura di installazione

Tre passi, nell'ordine. L'installer controlla il server prima di toccare qualcosa.

  1. Prepara un server nuovo

    Ubuntu 24.04 o 26.04 LTS appena creato, amd64, almeno 1 GB di RAM e 10 GB di disco liberi, accesso root via SSH. L'installer prende in mano nginx, PHP, MariaDB e SSH: usa un server dedicato.

  2. Lancia il comando

    $ curl -fsSL https://get.cloudground.it | sudo bash

    Se trova problemi (sistema, memoria, disco, porte occupate) li elenca tutti insieme e si ferma senza toccare nulla. Lo script verifica lo SHA-256 della release e il manifesto firmato.

  3. Apri il link di setup

    Alla fine stampa un indirizzo https://<ip>:8443/setup/… valido 24 ore, che funziona una volta. Crei l'amministratore, poi il primo sito.

Installa CloudGround

Da un server Ubuntu appena creato al pannello che risponde sulla porta 8443, con il tuo account amministratore.

In questo tutorial installi CloudGround su un server nuovo e crei l'account amministratore. Alla fine apri il pannello nel browser.

Ti serve

  • Un server Ubuntu 24.04 o 26.04 LTS appena creato, amd64, con almeno 1 GB di RAM e 10 GB di disco liberi
  • Accesso root via SSH
  • Le porte 80 e 443 libere

Usa un server dedicato

L'installer prende in mano nginx, PHP, MariaDB e la configurazione di SSH. Installalo solo su un server nuovo, o su uno che puoi ricreare.

Lancia l'installer

Entra nel server come root:

bash
ssh root@<ip-del-server>

<ip-del-server> è l'indirizzo pubblico del server. Poi lancia l'installer:

bash
$ curl -fsSL https://get.cloudground.it | sudo bash

Lo script installa CloudGround v0.2.0. Scarica la release da GitHub, lancia il suo cgctl solo se ha lo SHA-256 che lo script indica, e cgctl non installa nulla il cui manifesto firmato non si verifica. Per controllare lo script prima di lanciarlo, vedi verifica l'installer.

Prima controlla la macchina, poi mostra nove passi:

Output
  ✓   1/9  Installing nginx, PHP, MariaDB, restic
  ✓   2/9  Creating users, directories and secrets
  ✓   3/9  Installing CloudGround binaries
  ✓   4/9  Tuning kernel and nginx workers
  ✓   5/9  Configuring nginx
  ✓   6/9  Tuning MariaDB
  ✓   7/9  Starting services
  ✓   8/9  Opening the firewall
  ✓   9/9  Log rotation and certificate renewal

Se il controllo della macchina trova dei problemi (sistema, architettura, memoria, disco, porte occupate), li elenca tutti insieme e si ferma senza toccare nulla. Correggili e rilancia lo stesso comando.

Apri il link di setup

Alla fine l'installer stampa un indirizzo come https://<ip-del-server>:8443/setup/<token>. Il link vale 24 ore e funziona una volta.

Il certificato è autofirmato

Il browser avvisa che il certificato non è valido: al primo avvio è normale. Accetta l'avviso per questo indirizzo; un certificato vero arriva quando colleghi un dominio.

Crea l'account amministratore

La pagina Primo accesso chiede email e password.

  1. Nome e Cognome sono facoltativi.
  2. Scrivi la tua email.
  3. Scegli una password di almeno 12 caratteri e ripetila in Conferma password.
  4. Premi Crea account.

Il pannello crea il primo amministratore e ti fa entrare. Vedi la dashboard, ancora senza siti.

Controlla che tutto giri

bash
$ systemctl is-active cloudground-agent cloudground-api

Entrambe le righe dicono active.
