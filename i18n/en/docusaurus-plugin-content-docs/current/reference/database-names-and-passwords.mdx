The same rules apply in the **New site** dialog, the site's **Database** tab, cgctl and the API.
The panel validates them as you type, and the server validates them again.

## Names {#names}

Database names and database user names follow the same rule:

| Rule | Value |
| --- | --- |
| Pattern | `^[a-z][a-z0-9_]{2,47}$` |
| Length | 3 to 48 characters |
| Allowed characters | lowercase letters `a`–`z`, digits, `_` |
| First character | a letter |

These names are reserved and rejected:

| Kind | Names |
| --- | --- |
| Names | `mysql`, `sys`, `performance_schema`, `information_schema`, `root`, `debian_sys_maint`, `mariadb_sys`, `mysql_sys`, `mariadb`, `mysqld`, `admin`, `test`, `phpmyadmin`, `cloudground`, `replication`, `repl`, `monitor`, `backup` |
| Prefixes | `cg` followed by a letter and `_` (for example `cgq_`, used for the panel's own accounts and scratch databases), `mysql_`, `sys_`, `mariadb_`, `test_` |
| Panel default pattern | `site_<n>`: only site number `<n>` can use it, and only when the panel picks it (see below) |

Names must be unique across the server:

- a database name already used by any site is rejected (the **New site** dialog shows *`<name>` is
  already used on this server*);
- a user name already used by any site is rejected the same way;
- databases and users are separate namespaces, so a user can share a name with a database (the
  primary user often does);
- the panel never adopts a database or user created outside it; that name is rejected.

## Default names {#defaults}

| Where | Database name | User name |
| --- | --- | --- |
| **New site** dialog | Suggested from the domain: every label except the last, joined with `_` (`blog.example.com` → `blog_example`). You can change it. | Same as the database name, until you change it |
| cgctl and the API, with no name given | `site_<id>` | `site_<id>` |

`<id>` is the site's number. If a suggested name would be reserved, it gets a `site_` prefix
(`test.example` → `site_test`).

## Passwords {#passwords}

| Rule | Value |
| --- | --- |
| Length | 12 to 256 characters |
| Rejected characters | `'`, `"`, `\`, and control characters |
| Spaces | not allowed at the start or end |
| Left blank | the panel generates one: 32 URL-safe characters |

The **New site** dialog pre-fills the field with a generated 24-character URL-safe password, which
you can keep or replace.

Why those three characters are rejected: wp-cli writes the primary user's password into
`wp-config.php` without escaping `'`, `"` and `\` correctly. A password containing one of them
would make WordPress use a different password, or break `wp-config.php` altogether. Leading and
trailing spaces are rejected because they are easily lost when you copy a password.

A password is displayed only if the panel generated it, and only once: in the new site's summary,
or right after you create a user or reset its password. The panel never shows it again. To get a
new one, set it from the **Database** tab.

## Privileges {#privileges}

| Panel setting | Granted on the database |
| --- | --- |
| **None** | nothing |
| **Read only** | `SELECT, SHOW VIEW` |
| **All privileges** | `ALL PRIVILEGES` |

Every user is created as `<name>@localhost`, so it can only connect from this server, with at most
50 concurrent connections.
