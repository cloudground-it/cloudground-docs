`PATCH /api/sites/<id>` changes one or more of a site's settings. Every field is optional: only the
fields you send are changed, and `null` is treated as not sent. The request body is JSON
(`Content-Type: application/json`).

## Fields {#fields}

**Who** is the role allowed to send the field. *manage* means an administrator, or an operator
assigned to the site.

| Field | Type | Sites | Allowed values | Default | Effect | Who |
| --- | --- | --- | --- | --- | --- | --- |
| `aliases` | list of strings | production (not staging) | plain hostnames other than the domain, no duplicates, at most 50, none used by another site; `[]` removes them all | none | extra hostnames the site responds to besides its domain; the Let's Encrypt certificate is reissued to cover new names | administrator |
| `profile` | string | all | `balanced`, `commerce`, `maximum` | `commerce` for WooCommerce, otherwise `balanced` | page cache lifetime, bypass rules, PHP process manager | manage |
| `cache_enabled` | boolean | all | `true`, `false` | on, except static and reverse proxy | turns the page cache on or off | manage |
| `cache_ttl_sec` | integer | all | 0 to 31536000 | 0 | how long a page stays cached; 0 uses the profile's lifetime | manage |
| `php_workers` | integer | all | 0 to 64 | 0 | maximum number of PHP workers; 0 sizes them automatically | manage |
| `hsts` | boolean | all | `true` only with a certificate valid for at least 14 more days | off | adds `Strict-Transport-Security: max-age=31536000` | manage |
| `php_version` | string | with PHP | an installed version; the site's current version is accepted even if no longer installed | set at creation | the site's PHP-FPM version | manage |
| `memory_limit_mb` | integer | with PHP | 64 to 4096 | 256, or 512 for WooCommerce | PHP `memory_limit` | manage |
| `upload_max_mb` | integer | with PHP | 1 to 2048 | 64 | `upload_max_filesize` and `post_max_size` | manage |
| `max_execution_seconds` | integer | with PHP | 10 to 600 | 120 | `max_execution_time`; the actual per-request limit is this value plus 10 s, with a minimum of 120 s | manage |
| `public_root` | string | all except reverse proxy | empty, or a relative path whose segments contain only letters, digits, `-` and `_`, with no symlink or file along the path | `public` for Laravel, otherwise empty | the directory served, inside the live release (`current/<public_root>`) | manage |
| `proxy_upstream` | string | reverse proxy | an `http` or `https` URL with no credentials, query string or fragment; stored in normalised form | set at creation | where requests are forwarded | administrator |
| `object_cache` | boolean | WordPress, WooCommerce | `true`, `false` | off | installs and enables the APCu object cache, or turns it off | manage |
| `memory_max_mb` | integer | all | 0, or 128 to 1048576 | 0: half the server's memory, at least 1024 MB | memory limit for the site's slice (`MemoryMax`); the site is throttled at 90% of it | administrator |
| `cpu_quota_pct` | integer | all | 0, or 10 to 25600; 100 equals one CPU | 0: no quota | CPU quota for the site's slice (`CPUQuota`) | administrator |
| `tasks_max` | integer | all | 0, or 32 to 65536 | 0: 512 | maximum number of processes in the site's slice (`TasksMax`) | administrator |
| `usage_alerts` | object | all | `{off, cpu_pct, memory_pct, disk_mb}`, replaced as a whole; percentages from 0 to 100, `disk_mb` from 0 | alerts on, CPU and memory at 90 % (0), no disk alert (0) | thresholds for [usage alerts](/docs/sites/resource-usage-and-limits#usage-alerts); does not change the site's configuration | manage |

Any other field in the body makes the request invalid.

## Profiles {#profiles}

| Profile | Cache lifetime | Served stale for up to | PHP process manager |
| --- | --- | --- | --- |
| `balanced` (Balanced) | 600 s | 7200 s | `ondemand`, except WooCommerce |
| `commerce` (Commerce) | 300 s | 3600 s | `dynamic` |
| `maximum` (Maximum) | 86400 s | 3 days | `dynamic` |

A non-zero `cache_ttl_sec` overrides the profile's lifetime.

## PHP workers {#php-workers}

When `php_workers` is 0, the worker limit is the site's memory divided by 80 MB, capped at three
per CPU. When you set a value, that value is used. Either way, the result is clamped between 2
and 64.

A site's memory is a quarter of the server's memory divided among all sites, with a minimum of
160 MB.

The memory budget check runs when the request includes `php_workers` or `memory_limit_mb` and the
site's worker count after the change is above 0. Workers × memory limit (256 MB, or 512 MB for
WooCommerce, if no limit is set) must not exceed the server's memory. Sending
`"allow_over_budget": true` skips the check. Only an administrator can send it.

## Responses {#answers}

| Code | When |
| --- | --- |
| `202` | `{"site": …, "task": …}`, plus `"warnings"` when there is something you should know |
| `400` | malformed body or unknown field; no fields; a value that breaks its rule, including an alias another site already uses (`{"error": …, "fields": {<field>: <message>}}`); PHP memory budget exceeded |
| `403` | `aliases`, `proxy_upstream`, `memory_max_mb`, `cpu_quota_pct` or `tasks_max` (with `fields`), or `allow_over_budget`, sent by anyone other than an administrator |
| `404` | the site does not exist, or is outside an operator's scope |
| `409` | `hsts: true` without a certificate valid for at least 14 more days |
| `503` | the panel is restarting; try again shortly |

The change is saved immediately and applied by the **Site settings** task. If the task fails, the
panel restores the previous values of any fields that no later request has changed.
