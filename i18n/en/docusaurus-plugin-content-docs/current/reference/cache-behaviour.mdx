## Sites with a page cache {#which-sites}

| Type | Page cache |
| --- | --- |
| WordPress, WooCommerce, PHP, Laravel | Yes, on by default. Turn it off with the **Page cache** switch. |
| Static | No. Files are served straight from disk. |
| Reverse proxy | No |

## Profiles {#profiles}

Cache lifetimes depend on the site's **Performance profile**.

| Profile | Fresh for | Served stale for up to | Disk space |
| --- | --- | --- | --- |
| Balanced (default, except WooCommerce) | 600 s | 7200 s | 1024 MB |
| Commerce (default for WooCommerce) | 300 s | 3600 s | 1024 MB |
| Maximum | 86400 s | 259200 s | 4096 MB |

- **Lifetime (TTL)** on the **Cache** tab overrides the profile's "fresh" lifetime. `0` means use
  the profile's value. It does not change how long an expired page can still be served.
- `200` and `301` responses are cached for the full lifetime; `404` responses for 60 seconds.
- Only `GET` and `HEAD` requests are cached.
- An expired page is served while it is being refreshed, and also when PHP returns an error, times
  out, or returns `500`/`503`.
- Concurrent requests for the same uncached page wait for a single regeneration, for up to 5 s.

## Bypass rules by site type {#bypass}

A request bypasses the cache if it is a `POST`, has a query string with anything other than
tracking parameters, has an `Authorization` header, carries one of the cookies below, or has a
path starting with one of the prefixes below.

| Type | Cookies (name starts with) | Paths |
| --- | --- | --- |
| WordPress | `wordpress_logged_in_`, `wp-postpass_`, `comment_author_`, `woocommerce_cart_hash`, `woocommerce_items_in_cart`, `wp_woocommerce_session_` | `/wp-admin`, `/wp-login.php`, `/wp-cron.php`, `/xmlrpc.php`, `/wp-json/`, `/feed` |
| WooCommerce | Same as WordPress | WordPress paths plus the store paths |
| PHP | WordPress cookies plus `PHPSESSID` | Same as WordPress |
| Laravel | any `*_session`, `XSRF-TOKEN`, `remember_web_` | `/login`, `/logout`, `/register`, `/password/`, `/forgot-password`, `/reset-password`, `/email/verify`, `/admin`, `/nova`, `/horizon`, `/telescope`, `/sanctum/`, `/livewire/`, `/broadcasting/` |

The store paths are `/cart`, `/checkout`, `/my-account`, `/addons`, `/wc-api` and `/?wc-ajax=`.
Every WooCommerce site bypasses them, as does any WordPress or PHP site on the Commerce profile.
Laravel sites never do.

A prefix matches up to the end of a path segment: `/feed` excludes `/feed/` but not `/feedback`.

A response that sets a cookie (`Set-Cookie`), or sends `Cache-Control: no-store` or `private`, is
never cached, whatever the site type.

## Tracking parameters {#tracking}

A query string made up only of these parameters shares the cache entry of the same page without
them: `utm_*`, `fbclid`, `gclid`, `gbraid`, `wbraid`, `msclkid`, `dclid`, `mc_cid`, `mc_eid`,
`_ga`, `_gl`, `igshid`, `yclid`, `twclid`, `ttclid`.

## Response header {#header}

`X-CloudGround-Cache` is added to PHP responses on sites with the page cache on.

| Value | Meaning |
| --- | --- |
| `HIT` | Served from cache |
| `MISS` | Not in cache; rendered by PHP |
| `BYPASS` | A bypass rule sent it to PHP |
| `EXPIRED` | Cache entry had expired; re-rendered by PHP |
| `STALE` | Expired, served as-is |
| `UPDATING` | Expired, served as-is while another request regenerates it |
| `REVALIDATED` | Expired, then confirmed still valid |

## Cache key and storage {#storage}

| Item | Value |
| --- | --- |
| Directory | `/var/cache/cloudground/<domain>` |
| Key | Scheme, method, host (lowercase, no port) and request URI |
| Entry file | MD5 of the key, in a two-level directory tree |
| Unread entries are evicted after | One week, or lifetime plus stale window if that is longer |

## Automatic purges {#automatic-purges}

On WordPress and WooCommerce, the panel's connector purges the affected pages:

| Change | Purged |
| --- | --- |
| A post or page is published, edited or deleted | Its URL, the home page, the archives it appears in, and the feeds |
| A post's categories or tags change | The post, and the archives for the terms added or removed |
| A comment is approved | The post and its comment feeds |
| A product's price, stock status or image changes | The product and the archives it appears in |
| Theme, plugins, menus, widgets, Customizer settings, site options, updates | The whole site |

The panel also purges the whole site after a WordPress update run from the panel, a release, a
restore, and a publish from staging.
