You choose a site's type when you create it, and you cannot change it later. In the API it is the
`type` field.

## Overview {#summary}

| | `wordpress` | `woocommerce` | `php` | `laravel` | `static` | `proxy` |
| --- | --- | --- | --- | --- | --- | --- |
| Name in the panel | WordPress | WooCommerce | PHP | Laravel | Static | Reverse proxy |
| PHP | yes | yes | yes | yes | no | no |
| Database at creation | yes | yes | optional | yes | optional | no |
| Page cache at creation | on | on | on | on | no | no |
| Default profile | Balanced | Commerce | Balanced | Balanced | Balanced | Balanced |
| Default public directory | release root | release root | release root | `public` | release root | — |
| Object cache | yes | yes | no | no | no | no |
| System scheduled tasks | WordPress cron every 5 minutes | WordPress cron every 5 minutes | — | — | — | — |

Static and reverse proxy sites never get a page cache, even if the request asks for one.

## What gets created {#what-creation-makes}

Every type gets the system user `cg-site-<id>`, the directory `/srv/sites/<domain>` containing
`releases/`, `current`, `shared/uploads`, `logs` and `tmp/sessions`, and a vhost. Types with PHP
also get their own PHP-FPM service. SFTP access starts turned off.

WordPress, WooCommerce and Laravel sites also get a primary database and a database user with all
privileges on it. PHP and static sites get one only if you ask for it at creation. You can pick the
names or let the panel suggest them (see [Database names and
passwords](/docs/reference/database-names-and-passwords)). More databases and users can be added to
any site later from the **Database** tab.

| Type | Contents of the first release |
| --- | --- |
| `wordpress` | WordPress installed with wp-cli, with the administrator you specified, `/%postname%/` permalinks, the panel connector in `wp-content/mu-plugins/` and `DISABLE_WP_CRON` set |
| `woocommerce` | same as `wordpress`, plus the WooCommerce plugin installed and activated |
| `php` | a placeholder `index.php` |
| `laravel` | a placeholder `index.php` in `public/` |
| `static` | a placeholder `index.html` |
| `proxy` | nothing; requests are forwarded to the upstream URL |

`wp-config.php` lives in `shared/` (mode 0600), and the release points to it with a relative
symlink. `wp-content/uploads` works the same way, pointing to `shared/uploads`.

## Creation fields {#creation-fields}

| Field | Types | Rule |
| --- | --- | --- |
| `domain` | all | required; a plain hostname, converted to lowercase |
| `type` | all | required; one of the six types |
| `aliases` | all | plain hostnames, none used by another site |
| `profile` | all | `balanced`, `commerce` or `maximum` |
| `php_version` | with PHP | an installed version; if omitted, the server default if installed, otherwise the newest |
| `cache_enabled` | with PHP | on if omitted |
| `object_cache` | `wordpress`, `woocommerce` | off if omitted |
| `title` | `wordpress`, `woocommerce` | optional; defaults to the domain if empty |
| `admin_email` | `wordpress`, `woocommerce` | required; a valid email address |
| `admin_user` | `wordpress`, `woocommerce` | required |
| `admin_password` | `wordpress`, `woocommerce` | required; at least 12 bytes |
| `proxy_upstream` | `proxy` | required; an `http` or `https` URL with no credentials, query string or fragment |

## PHP defaults by type {#php-by-type}

| | WooCommerce | All other types with PHP |
| --- | --- | --- |
| Default `memory_limit` | 512 MB | 256 MB |
| `upload_max_filesize` and `post_max_size` | 64 MB | 64 MB |
| `max_execution_time` | 120 s | 120 s |
| OPcache | 128 MB, 16 MB interned strings, 20000 files | 64 MB, 8 MB interned strings, 10000 files |
| APCu | 64 MB | 32 MB |

The process manager is `ondemand` (no idle workers) for non-WooCommerce sites on the Balanced
profile, and `dynamic` for everything else.

## Cache bypass rules {#cache-bypass}

Requests that carry one of these cookies, or fall under one of these paths, are not served from
the page cache. Neither are `POST` requests or responses that set a cookie.

| Type | Cookies | Paths |
| --- | --- | --- |
| `wordpress` | `wordpress_logged_in_`, `wp-postpass_`, `comment_author_`, `woocommerce_cart_hash`, `woocommerce_items_in_cart`, `wp_woocommerce_session_` | `/wp-admin`, `/wp-login.php`, `/wp-cron.php`, `/xmlrpc.php`, `/wp-json/`, `/feed` |
| `woocommerce` | same as `wordpress` | same as `wordpress`, plus `/cart`, `/checkout`, `/my-account`, `/addons`, `/wc-api`, `/?wc-ajax=` |
| `php` | same as `wordpress`, plus `PHPSESSID` | same as `wordpress` |
| `laravel` | `_session=`, `XSRF-TOKEN=`, `remember_web_` | `/login`, `/logout`, `/register`, `/password/`, `/forgot-password`, `/reset-password`, `/email/verify`, `/admin`, `/nova`, `/horizon`, `/telescope`, `/sanctum/`, `/livewire/`, `/broadcasting/` |

On the Commerce profile, `wordpress` and `php` sites also bypass the WooCommerce paths.
