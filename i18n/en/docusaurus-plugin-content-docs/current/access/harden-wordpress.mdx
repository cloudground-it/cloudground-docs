You can turn on the most common WordPress protections, the ones usually handled by plugins, directly
from the panel, one at a time. The **recommended set** doesn't change anything for visitors,
WooCommerce customers or Jetpack.

## Turn on protections {#turn-them-on}

1. Open the site, go to the **WordPress** tab and find the **Hardening** section.
2. Turn on the protections you want, or press **Apply the recommended set** (everything except the
   login address).
3. Save. The page cache is purged.

All protections are off by default.

| Protection | What it does |
| --- | --- |
| **Turn XML-RPC off** | `xmlrpc.php` returns 403, except for the addresses in **XML-RPC exceptions** (IP addresses or networks, one per line, up to 50) and Jetpack's own signed requests. The WordPress mobile app and some publishing tools use XML-RPC. |
| **Turn the file editor off** | Theme and plugin code can't be edited from wp-admin, regardless of what `wp-config.php` says. |
| **Hide the WordPress version** | Removes the version from the page head, from feeds and from WordPress's file URLs. Browsers still fetch new files after an update. |
| **Block readme and licence files** | `readme.html`, `license.txt` and plugin and theme readme files return 404, since they reveal versions. |
| **Login address** | Moves the sign-in page. |

## Move the login page {#login-address}

In **Login address**, enter 3 to 64 lowercase letters, digits and hyphens, for example `entrance`. If
you leave it empty, the site keeps `wp-login.php`. Once it's set:

- The sign-in page lives at `/entrance`, including the two-factor step and the lost-password link.
- `wp-login.php` returns 404 however it's spelled, and `/login` and `/admin` no longer redirect.
- wp-admin returns 404 to visitors who aren't signed in (`admin-ajax.php` and `admin-post.php` stay
  open).
- The new page bypasses the page cache.

The panel rejects an address that clashes with a WordPress or WooCommerce path. Emails sent from
wp-cli or from system scheduled tasks still link to `wp-login.php`. Write the address down, because
nobody can look it up for you.

## Use the API {#with-the-api}

`PUT /api/sites/<id>/wp/hardening` with `{"xmlrpc_off", "xmlrpc_allow": [...], "file_edit_off",
"hide_version", "block_readme", "login_path"}`, and `PUT /api/sites/<id>/wp/two-factor` with
`{"mode": "off"}`, `optional` or `required`.
