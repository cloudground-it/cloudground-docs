Once a day the panel looks up the installed versions of WordPress, its plugins and its themes in a
public vulnerability database. What affects your versions shows in the site's **Security** tab and raises
an alert. The panel never updates anything by itself: updating stays your choice.

## Read the results {#read-the-results}

1. Open the site and its **Security** tab, **Known vulnerabilities** box.
2. At the top you see the outcome: **none known**, **N found**, **first check soon** or **off**.
3. The table lists, for each vulnerability: the kind (**WordPress**, **Plugin** or **Theme**),
   **Installed**, **Severity** (**Critical**, **High**, **Medium**, **Low**), the **Vulnerability** with
   its CVE and a link to the advisory, and the **Fix**:
   - **Update to `<version>`**: a fixed version exists;
   - **No fix yet**: no version solves it yet;
   - **Check the advisory**: the database does not say which version solves it.
4. Under the table you find **Last check** and **Components checked**.

To check right away press **Check now**. The check runs as a task; if it fails, the page says **The last
check, `<when>`, did not complete** and shows the list from the check before.

## The alert {#the-alert}

A site with vulnerabilities raises a **Vulnerability** alert, which also reaches the webhook like any
other alert (see [alerts and notifications](/docs/server/alerts-and-notifications)). It is an **error**
if one is high or critical, otherwise a **warning**. When a new vulnerability appears the alert comes
back, even if you had dismissed it.

## Turn the check off {#turn-it-off}

The check is on by default. To turn it off, in **Settings** untick **Check WordPress sites for known
vulnerabilities** and save. With cgctl: `cgctl settings set vulnerability_check 0` (and `1` to turn it back
on). The **Security** tab then says **off**.

The check sends nothing but the name and version of each component out of the server: never the domain
or anything else about the server. How it works and where the data comes from is in [security
checks](/docs/explanation/security-scans).
