Once a day, the panel looks up the installed versions of WordPress, its plugins and its themes in a
public vulnerability database. Anything that affects your versions shows up on the site's **Security**
tab and triggers an alert. The panel never updates anything on its own. Updating is always your call.

## Read the results {#read-the-results}

1. Open the site, go to the **Security** tab and find the **Known vulnerabilities** box.
2. The top shows the overall result: **none known**, **N found**, **first check soon** or **off**.
3. The table lists each vulnerability with its component type (**WordPress**, **Plugin** or
   **Theme**), the **Installed** version, the **Severity** (**Critical**, **High**, **Medium**,
   **Low**), the **Vulnerability** with its CVE and a link to the advisory, and the **Fix**:
   - **Update to `<version>`**: a fixed version is available.
   - **No fix yet**: no version fixes it yet.
   - **Check the advisory**: the database doesn't say which version fixes it.
4. Below the table you'll find **Last check** and **Components checked**.

To run a check right away, press **Check now**. The check runs as a task. If it fails, the page shows
**The last check, `<when>`, did not complete** and keeps the results from the previous check.

## Alerts {#the-alert}

A site with vulnerabilities triggers a **Vulnerability** alert, which also goes to the webhook like
any other alert (see [alerts and notifications](/docs/server/alerts-and-notifications)). The alert is
an **error** if any vulnerability is high or critical, and a **warning** otherwise. When a new
vulnerability appears, the alert comes back, even if you dismissed it.

## Turn off the check {#turn-it-off}

The check is on by default. To turn it off, open **Settings**, clear
**Check WordPress sites for known vulnerabilities** and save. With cgctl, run
`cgctl settings set vulnerability_check 0` (use `1` to turn it back on). The **Security** tab then
shows **off**.

The only data the check sends off the server is the name and version of each component. It never
sends the domain or anything else about the server. For how it works and where the data comes from,
see [security checks](/docs/explanation/security-scans).
