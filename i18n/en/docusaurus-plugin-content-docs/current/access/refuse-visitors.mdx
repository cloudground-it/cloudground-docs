Any site can refuse visitors with **403**. Rules are set per
site and take effect as soon as you save. A site with no rules has no added cost. How nginx
applies them is in [address blocking](/docs/explanation/blocking#site-rules).

## Write the rules {#write-the-rules}

1. Open **Blocking** under the **Server** group and find the **Per-site rules** box.
2. Press **Add rules for a site**, or **Edit** on the row of a site that already has rules.
3. Choose the **Site**.
4. Fill in what you need:
   - **Addresses and networks**: one per line, such as `203.0.113.4` or `203.0.113.0/24`.
   - **User agents**: one per line. Any visitor whose User-Agent contains one of these strings,
     case-insensitively, is refused. The **AI crawlers** and **SEO crawlers** buttons add ready-made
     lists.
   - **Countries**: choose from the list.
   - **Serve only these countries**: refuses every other country, including addresses with no known
     country.
5. Press **Save**.

Limits: 500 networks per site, none wider than /8 (IPv4) or /16 (IPv6). 50 user agents of 2 to 100
printable characters each, without `"`, `\`, `$`, `{` or `}`. 50 countries. The panel rejects rules
that include your own address, loopback or the server.

To clear everything, press **Remove all rules**.

## What's never refused {#never-refused}

- The server's own addresses and loopback, so uptime checks, Performance Guard and the cache warmer
  still get through.
- Port 80, which stays open for certificate validation.

:::note

Anyone can send any User-Agent. The user agent rule stops crawlers that identify themselves, not an attacker.

:::

## Country data {#country-data}

Countries are looked up in DB-IP's **IP to Country Lite** database (licensed CC BY 4.0, with the
attribution shown in the panel's country list). The server downloads it automatically, with no
account or key, and refreshes it after 35 days. If a refresh fails, it keeps the old copy. If there's
no copy and no network access, saving country rules fails and nothing changes.

## Use cgctl or the API {#with-cgctl-or-the-api}

```bash
cgctl sites block <site-id> '{"addresses": ["203.0.113.0/24"], "user_agents": ["badbot"], "countries": ["NL"], "allow_countries_only": false}'
```

Passing `'{}'` removes every rule. Through the API, send the same object with
`PUT /api/sites/<id>/blocking`.
