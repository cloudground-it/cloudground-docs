`cgctl` is the panel's command-line client. It's installed on the server in `/usr/local/bin`. In
scripts, it authenticates with an **API token**: a `cgt_…` credential that acts as the administrator
who created it, so you don't need a password or a code on every call.

A token can do anything its owner can, except manage accounts, users, tokens and the site shell.
Those actions need a browser session signed in with a password. So a stolen token can't create
another token or a new administrator.

## Create a token {#create-a-token}

Create tokens from a session signed in with your password: a token can't create other tokens.

1. In the panel, open **Security** from your account menu and find the **API tokens** card.
2. Enter a **Name**, 1 to 64 characters, the token's label in the list.
3. In **Expires**, choose **30 days**, **90 days**, **365 days** or **never expires**.
4. Press **Create token**.

The panel shows the `cgt_…` value once. **Copy it now, because the panel never shows it again.** It
only stores a fingerprint of the token.

With cgctl, on the server as root:

```bash prompt
export CLOUDGROUND_EMAIL='<email>'
read -rs CLOUDGROUND_PASSWORD && export CLOUDGROUND_PASSWORD
cgctl tokens create "<name>" 90
```

- `90` is the lifetime in days, from 1 to 365. If you leave it out or pass `0`, the token never
  expires.
- If your account uses two-step verification, also set `CLOUDGROUND_TOTP='<code>'` with a code from
  your app.

The response includes a `token` field with the `cgt_…` value.

## Configure cgctl {#configure-cgctl}

On the server, write the token to cgctl's configuration file, readable only by root:

```bash prompt
install -m 0600 /dev/null /etc/cloudground/cgctl.env
echo "CLOUDGROUND_TOKEN=cgt_…" > /etc/cloudground/cgctl.env
cgctl status
```

If `CLOUDGROUND_URL` isn't set, cgctl talks to the panel over the local socket
`unix:///run/cloudground/api.sock`. Environment variables take precedence over the file, so for a
one-off command `CLOUDGROUND_TOKEN=cgt_… cgctl status` is enough. Instead of the token itself, you
can point `CLOUDGROUND_TOKEN_FILE` at a file that contains it.

## Use cgctl from another computer {#remote}

Copy `cgctl` to your computer and point it at the panel's HTTPS address:

```bash
export CLOUDGROUND_URL='https://<panel-domain>'
export CLOUDGROUND_TOKEN='cgt_…'
cgctl sites list
```

cgctl verifies the certificate. The `https://<ip>:8443` address uses a self-signed certificate, so
there it needs `CLOUDGROUND_INSECURE=1`. Better to
[give the panel a domain](/docs/server/panel-domain). cgctl only accepts `http://` for an address on
the local machine.

## Wait for a task to finish {#wait}

Many commands start a background task. With `--wait`, cgctl follows the task until it finishes and
exits with code 0 only if it succeeded:

```bash
cgctl --wait backup run <site-id>
```

The [CLI reference](/docs/cli) lists every command, variable and exit code.

## List and revoke tokens {#revoke}

```bash prompt
cgctl tokens list
cgctl tokens revoke <token-id>
```

Like `tokens create`, these commands need your email and password, and you must run them with
`CLOUDGROUND_URL='https://127.0.0.1:8443'`. In the panel, pressing **Revoke** on the token's row in
**Security** does the same thing. Any administrator can revoke any token. The panel also revokes an
account's tokens automatically when its password is changed or reset, when it turns off two-step
verification, when it's disabled, demoted or deleted, and when you run `panel-api recover-admin`.

Token creation, revocation and every action taken with a token are recorded in the **Audit log**,
along with the token's name.
