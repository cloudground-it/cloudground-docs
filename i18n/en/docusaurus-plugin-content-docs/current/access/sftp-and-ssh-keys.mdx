Each site has its own system user, `cg-site-<id>`, locked into the site's folder. SFTP transfers files
as that user, with no shell and no access to other sites. On a new site, SFTP access is **off**, and
that includes keys.

## Enable SFTP access {#enable-sftp}

*Since v0.2.0.* You can allow sign-in with SSH keys only, which is the recommended setup. Before
v0.2.0, a password was always required.

1. Open the site and go to the **SFTP / SSH** tab.
2. In **SFTP access**, under **How to sign in**, keep **SSH keys only** selected.
3. If the site doesn't have an SSH key yet, paste the key you'll sign in with into **Public key**.
4. Press **Enable with keys only**.

With keys only, there is no password at all. The server doesn't even ask for one, so there's nothing
to guess. To add more keys, see [Add an SSH key](#add-a-key).

### Enable SFTP with a password {#enable-with-a-password}

1. Under **How to sign in**, choose **Password or SSH key**.
2. Enter an **SFTP password** with at least 12 characters.
3. Press **Enable SFTP**.

:::caution[Passwords can be guessed]

SFTP usernames follow the pattern `cg-site-<id>`, so they're easy to guess. For now, the only
protection against repeated wrong passwords is the SSH server's own per-connection limit. CloudGround
doesn't yet block an address that keeps failing. Use a long, random password, or use keys only.

:::

To switch an account from one method to the other, select it and press **Switch to keys only** or
**Switch to a password**.

The **Connection details** box shows everything your client needs: **Host**, **Port**, **Username**,
**Folder** and a ready-to-copy **Command**:

```bash
sftp cg-site-<id>@<host>
```

`<host>` is the address you used to open the panel. If SSH on the server isn't listening on port 22,
the command also includes `-P <port>`. Inside the session, the site's folder is the root, `/`.

To change the password for password sign-in, enter a new one and press **Change password**.

## Add an SSH key {#add-a-key}

Keys are the recommended option for developers, since there's no password to share.

1. In the **SSH keys** section, paste a single line into **Public key**, in the format
   `<type> <base64> [comment]`.
2. Leave **Type** set to **SFTP only**.
3. Press **Add key**.

The panel accepts these key types: `ssh-ed25519`, `ssh-rsa`, `ecdsa-sha2-nistp256`,
`ecdsa-sha2-nistp384`, `ecdsa-sha2-nistp521`, `sk-ssh-ed25519@openssh.com` and
`sk-ecdsa-sha2-nistp256@openssh.com`. It rejects multiple lines at once, options before the key type
(`command="…"`) and keys that are already added. The comment becomes the key's label.

Each key is listed with its `SHA256:…` fingerprint, the same one `ssh-keygen -lf` prints. Compare it
with the fingerprint of the key you received.

:::note[Keys depend on SFTP access]

A key only works while SFTP access is on. Turning off access disables both the password and the keys.

:::

## Remove a key {#remove-a-key}

Press the bin icon next to the key and confirm. The key stops working from the next sign-in.

## Disable SFTP access {#disable-sftp}

In **SFTP access**, press **Disable**. The panel locks out the site user, both by password and by key.
The keys stay in the list and start working again when you re-enable access.

## Use cgctl or the API {#from-the-api}

The API supports the same operations through `POST /api/sites/<id>/sftp`:

- `{"enable": true, "public_key": "ssh-ed25519 …"}` adds the key and enables access with keys only.
- `{"enable": true, "keys_only": true}` enables access with keys only, or switches to it.
- `{"enable": true, "keys_only": false, "password": "…"}` enables access with a password.
- `{"enable": false}` disables access.

`GET`, `POST` and `DELETE` on `/api/sites/<id>/ssh-keys` list, add and remove keys. With
[cgctl](/docs/cli#sftp):

```bash
cgctl sftp keys-only <site-id> ~/.ssh/id_ed25519.pub
cgctl sftp password <site-id> < password.txt
cgctl sftp off <site-id>
```
