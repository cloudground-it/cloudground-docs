Every site has its own system user, `cg-site-<id>`, confined to the site's folder. SFTP moves files
as that user: no shell, no access to other sites. A new site starts with SFTP access **off**, keys
included.

## Turn on SFTP access {#enable-sftp}

*Since v0.2.0.* Access can be with SSH keys only, the recommended way. Before v0.2.0 it always
needed a password.

1. Open the site and go to the **SFTP / SSH** tab.
2. In **SFTP access**, under **How to sign in**, leave **SSH keys only** selected.
3. If the site has no SSH key yet, paste the one that will sign in into **Public key**.
4. Press **Enable with keys only**.

With keys only the login has no password: the server does not even ask for one, so there is
nothing to guess. To add more keys, see [below](#add-a-key).

### With a password {#enable-with-a-password}

1. Under **How to sign in**, choose **Password or SSH key**.
2. Type an **SFTP password** of at least 12 characters.
3. Press **Enable SFTP**.

:::caution[A password can be guessed]

SFTP usernames have the form `cg-site-<id>`, so they are easy to guess. Against repeated wrong
passwords, only the SSH server's own limits per connection apply for now: CloudGround does not yet
block an address that keeps failing. Use a long, random password, or keys only.

:::

To switch an account from one way to the other, choose it and press **Switch to keys only** or
**Switch to a password**.

The **Connection details** box shows what the client needs: **Host**, **Port**, **Username**,
**Folder** and the **Command**, ready to copy:

```bash
sftp cg-site-<id>@<host>
```

`<host>` is the address you opened the panel with. When SSH on the server does not listen on port
22, the command also carries `-P <port>`. Inside the session the site's folder is the root `/`.

To change the password of a password login, type a new one and press **Change password**.

## Add an SSH key {#add-a-key}

Keys are the recommended way for developers: no password to share.

1. In the **SSH keys** section, paste a single line into **Public key**, in the form
   `<type> <base64> [comment]`.
2. Leave **Type** on **SFTP only**.
3. Press **Add key**.

The panel accepts the types `ssh-ed25519`, `ssh-rsa`, `ecdsa-sha2-nistp256`, `ecdsa-sha2-nistp384`,
`ecdsa-sha2-nistp521`, `sk-ssh-ed25519@openssh.com` and `sk-ecdsa-sha2-nistp256@openssh.com`. It
refuses several lines at once, options before the type (`command="…"`) and a key that is already
there. The comment becomes the key's label.

Each key is listed with its `SHA256:…` fingerprint, the same one `ssh-keygen -lf` prints: compare it
with the fingerprint of the key you were given.

:::note[Keys follow SFTP access]

A key works only while SFTP access is on. Turning access off stops both the password and the keys.

:::

## Remove a key {#remove-a-key}

Press the bin icon next to the key and confirm. The key stops working from the next sign-in.

## Turn off SFTP access {#disable-sftp}

In **SFTP access** press **Disable**. The panel locks the site user out, by password and by key. The
keys stay in the list and work again when you turn access back on.

## From cgctl or the API {#from-the-api}

The API offers the same operations on `POST /api/sites/<id>/sftp`:

- `{"enable": true, "public_key": "ssh-ed25519 …"}` adds the key and turns access on with keys only;
- `{"enable": true, "keys_only": true}` turns access on (or switches it) to keys only;
- `{"enable": true, "keys_only": false, "password": "…"}` turns it on with a password;
- `{"enable": false}` turns it off.

`GET`, `POST` and `DELETE` on `/api/sites/<id>/ssh-keys` list, add and remove keys. With
[cgctl](/docs/cli#sftp):

```bash
cgctl sftp keys-only <site-id> ~/.ssh/id_ed25519.pub
cgctl sftp password <site-id> < password.txt
cgctl sftp off <site-id>
```
