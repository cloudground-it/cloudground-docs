The panel is always available at `https://<server-ip>:8443`, with a self-signed certificate. Once you
give it a domain, it's also available at `https://<domain>` with a valid certificate. The IP address
keeps working, so you can still reach the panel if the domain breaks.

## Set the Let's Encrypt email {#set-the-email}

1. Open **Settings**.
2. In the **Certificates** card, enter an address under **Let's Encrypt email**. Let's Encrypt uses it
   for registration and expiry notices.
3. Click **Save**.

## Request the certificate {#request-the-certificate}

1. In the **Panel domain and HTTPS** card, enter the domain under **Domain**, for example
   `panel.example.com`.
2. Click **Secure the panel with Let's Encrypt**.

The panel starts a task that writes the nginx configuration for the domain, checks that the domain
resolves to this server, and requests the certificate. When the task finishes, the card reads **The
panel answers on `<domain>`, with a certificate that renews automatically.**

Go to `https://<domain>` and sign in.

In the API: `POST /api/panel/certificate` with `{"domain": "<domain>"}`.

## Move the panel to another domain {#move-the-panel}

Point the new domain at the server first. Then enter it under **Domain** and click **Move the panel
to this domain**.

## Renewal {#renewal}

Every 12 hours the panel checks the certificate and renews it when it's due. If the certificate
hasn't changed, nothing happens. If it has, nginx loads it without dropping open connections.

## Restrict access to the panel {#restrict-access}

Rules you add to `/etc/cloudground/panel-access.conf` apply to both the panel domain and port 8443,
and the panel never overwrites them. For example, to allow a single address:

```nginx
allow <your-ip>;
deny all;
```

Then, on the server:

```bash prompt
nginx -t && systemctl reload nginx
```

:::warning[Don't lock yourself out]

If your IP address changes, the panel stops responding to you. Keep SSH access to the server so you
can remove the rule.

:::
