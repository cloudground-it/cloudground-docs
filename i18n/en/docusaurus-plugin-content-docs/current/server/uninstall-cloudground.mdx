`cgctl uninstall` removes CloudGround from the server. By default it keeps the sites' files, their
databases and every backup. Options also delete the sites and remove the packages the
installer added. You can't uninstall from the panel.

## Preview the changes {#plan}

On the server, as root:

```bash prompt
cgctl uninstall --plan
```

It prints every action, one per line, followed by what will be kept, and changes nothing. Add the
options you plan to use (`--remove-sites`, `--purge-packages`) to include their actions too.

## Uninstall and keep the sites {#keep-the-sites}

```bash prompt
cgctl uninstall
```

It lists what it will keep and asks `Remove CloudGround? [y/N]`. Type `y`. With `--yes` it skips the
question.

What happens to each part:

| What | No options | With `--remove-sites` |
| --- | --- | --- |
| CloudGround's services, units, binaries, its nginx, sshd, kernel, log rotation, cron and certbot hook files, the `cloudground` user, the panel's state | removed | removed |
| *Since v0.3.0.* quarantined files and the malware scan's signatures (the ClamAV package stays) | removed | removed |
| *Since v0.3.0.* the block list's `inet cloudground` table | removed | removed |
| `nginx.conf` and the distribution's default site | restored to their original state | restored to their original state |
| site files under `/srv/sites` | **kept**, but nothing serves them | deleted |
| site users `cg-site-<id>` | **kept and locked**, since they own the files | deleted, along with their groups |
| site databases and database users, MariaDB and its tuning file | **kept**, and MariaDB keeps running | CloudGround's dropped; tuning file removed |
| site certificates (`/etc/letsencrypt/live/<domain>`) | kept | deleted |
| certificates you uploaded for a site | moved to `/root/cloudground-uninstall/custom-certs` | deleted |
| backups, in their repository | **never touched** | **never touched** |

Kept certificates stop renewing, because renewal relied on CloudGround's web folder for certificate
challenges, and that folder is gone. At the end, the uninstall lists them along with the commands to
renew one through another web server (`certbot certonly --webroot -w <root> --cert-name <domain> -d <domain>`)
or remove it (`certbot delete --cert-name <domain>`).

## Uninstall and delete the sites {#remove-sites}

:::danger[This deletes your sites]

`--remove-sites` deletes every site's files and users, CloudGround's databases and database users,
and the sites' certificates. This can't be undone. Backups in the repository are kept.

:::

```bash prompt
cgctl uninstall --remove-sites
```

It tells you how many sites and databases it will delete and asks you to type the server's hostname.
`--yes` isn't enough here. To confirm without the prompt, pass the hostname:

```bash prompt
cgctl uninstall --remove-sites --confirm <hostname>
```

`<hostname>` is what the `hostname` command prints on the server. Any other value changes nothing.

## Remove the packages too {#purge-packages}

```bash prompt
cgctl uninstall --remove-sites --purge-packages
```

`--purge-packages` runs last. It removes the packages the installer added because they were missing
(nginx, certbot and PHP), then any dependencies only they needed (apt's autoremove rule; packages you
put on hold stay). It also removes the `ondrej/php` repository it added, the restic, wp-cli and
composer binaries it placed in `/usr/local/bin`, and unloads the AppArmor profiles of the packages it
purged.

- Packages that were on the server before the install are never removed, and neither are `curl`,
  `git`, `cron` or the other base tools.
- MariaDB is removed only with `--remove-sites`, and only if it holds no other databases. Its data
  folder `/var/lib/mysql` stays.

## What's saved for you {#kept}

Before removing anything, the uninstall copies these to `/root/cloudground-uninstall/` (root only):

| Path | Contents |
| --- | --- |
| `state/` | the panel's database and its key, unchanged, readable by a CloudGround of the same or a newer release |
| `backup.env` | the backup repository and its password, without which no backup can be read |
| `README.txt` | what each file is, and every repository the panel used |
| `custom-certs/` | the certificates you uploaded, without `--remove-sites` |
| `uninstall.log` | what the run did |

:::warning[`backup.env` is plain text]

It contains the repository password. Store it off the server, then delete it.

:::

To list your backups with it:

```bash prompt
cd /root/cloudground-uninstall && set -a && . ./backup.env && set +a && restic snapshots
```

If you uninstall again later, whatever an earlier uninstall saved is moved into `earlier-<date>/`,
never overwritten.

## If it stops partway {#rerun}

When an action fails, it's reported and the rest carry on. The command then exits with 1 and lists the
failures. Fix the cause and run `cgctl uninstall` again: every action can be repeated. On a server
with nothing of CloudGround left, it prints `CloudGround is not installed here: nothing to remove`.
