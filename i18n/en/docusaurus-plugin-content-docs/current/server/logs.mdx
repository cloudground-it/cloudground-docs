There are two sets of logs: server logs, on the **Logs** page, and per-site logs, on each site's
**Logs** tab. The panel shows the most recent lines. Click **Refresh** to reload them.

## Server logs {#server-logs}

Open **Logs** from the menu. It has these tabs:

| Tab | Contents | Location |
| --- | --- | --- |
| **Nginx access** | nginx's main access log. | `/var/log/nginx/access.log` |
| **Nginx error** | nginx errors. | `/var/log/nginx/error.log` |
| **PHP-FPM** | The journal of every site's PHP processes. | journal, `cloudground-php-*.service` |
| **MariaDB** | Database errors. | `/var/log/mysql/error.log` |
| **API** | The panel. | journal, `cloudground-api.service` |
| **Agent** | The agent that does the root-level work. | journal, `cloudground-agent.service` |

Operators can't see this page, because server logs cover every site.

## Site logs {#site-logs}

Open the site and go to the **Logs** tab. It has **Access**, **Errors** and **PHP errors** tabs, each
showing the last 200 lines. On disk, they live in `/var/log/cloudground/<domain>/`:

| Tab | File |
| --- | --- |
| **Access** | `access.log` |
| **Errors** | `error.log` |
| **PHP errors** | `php-error.log` |

A log that doesn't exist yet shows *(log is empty or not created yet)*.

## Download a site's whole logs {#download}

The panel shows only the last lines. For the whole file, open the site's **Logs** tab and look at the
**Download the logs** card: it lists the access and error logs, the current ones (`access.log`,
`error.log`) and the rotated ones (`access.log.1`, `access.log.2.gz`, …), with their size and when they
were last written. Click **Download** next to the file you need.

- Rotated logs older than a day are compressed (`.gz`): they download as they are and open with
  `gunzip` or `zcat`. Fourteen days are kept.
- The current log is sent as it is at that moment, while nginx goes on writing to it: the size shown is
  only a hint, and if a rotation empties it during the download the file ends there. Rotated logs do
  not change.
- The card is there only for administrators and for operators assigned to the site, not for read-only
  accounts. Every download is recorded in the audit log (`site.logs.download`).
- Only the site's access and error logs can be downloaded: not `php-error.log`, nor any other file in
  the folder.

From the command line:

```bash prompt
cgctl logs <site-id>
cgctl logs <site-id> access.log.2.gz
cgctl logs <site-id> error.log -        # to standard output
```

The second command writes `access.log.2.gz` in the current folder (or to the file given as the third
argument) and does not overwrite a file that exists. It works for files of any size.

## On the server {#on-the-server}

As root, read the journal logs with `journalctl`:

```bash prompt
journalctl -u cloudground-api -u cloudground-agent -n 100
```

## From the API {#from-the-api}

`GET /api/logs?source=<source>&lines=<n>` returns a server log. `source` is `nginx-access`,
`nginx-error`, `php-error`, `mariadb`, `api` or `agent`, and `lines` is 1 to 2000 (200 by default).
`GET /api/sites/<id>/logs?source=<kind>` returns a site log, where `source` is `access`, `error` or
`php`. Lines longer than 8 KiB are truncated. `GET /api/sites/<id>/logs/files` lists the logs that can be
downloaded and `GET /api/sites/<id>/logs/download?file=<name>` downloads a whole file, for accounts that
manage the site.
