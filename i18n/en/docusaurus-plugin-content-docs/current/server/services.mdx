The **Services** page, in the **Server** group, lists the system services that run the sites:

| Row | System service |
| --- | --- |
| `nginx` | `nginx` |
| `mariadb` | `mariadb` |
| `redis` | `redis-server`, only where it is installed |
| **Site PHP** | every `cloudground-php-*.service`, one per site |

For each service you see **State**, **At boot** (*yes* or *no*), **Memory**,
**Started** and **Version**. The **Site PHP** row sums up the PHP processes: how many are running
and, when one is not, which.

A service that is not installed has no row. A new server does not get Redis (the sites' object cache
uses APCu), so there is no `redis` row. A server upgraded from an earlier version keeps Redis switched
off, and its row says **disabled**. The `nginx` and `mariadb` rows are always there.

## Read the state {#read-the-state}

| State | Meaning |
| --- | --- |
| **running** | The service is running. |
| **failed** | The service stopped with an error. |
| **disabled** | The service is off and does not start on boot, on purpose. |
| **stopped** | The service is not running, but it is meant to. |

A **failed** or **stopped** service raises an alert on the dashboard: see
[alerts and notifications](./alerts-and-notifications.mdx).

## The tools' units {#helper-units}

*Since v0.3.0.* For a backup, a database dump or a certificate, the agent does not run `restic`,
`mariadb-dump`, the `mariadb` client or `certbot` in its own process: each runs in a transient unit
`cg-helper-<tool>-<n>.service`, in the `cg-helper.slice` slice, with the agent's own sandbox and a
memory cap of its own, 75% of the server's memory. If one of these tools goes over the cap, the kernel
stops it: that operation, for example a backup, fails, and the panel and the agent carry on. At start the
agent stops any units left by an earlier run of itself.

The `cloudground-agent.service` unit has a memory limit of its own: over 768 MB the kernel slows it, and
over 1 GB it stops the process that exceeded it. The transient units show in `systemctl list-units
'cg-helper-*'` only while they work. Why they sit outside the agent's unit is explained in
[the architecture](/docs/explanation/architecture#the-agent).

## Restart a service {#restart}

1. Open **Services**.
2. Press **Restart** on the service's row.
3. Confirm.

A restart interrupts requests in flight for a few seconds. The panel waits for the system to finish,
3 minutes at most: MariaDB can be slow to come back.

A **disabled** service has no **Restart** button: it is off on purpose (Redis, on an upgraded server)
and a restart would turn it on. The **Site PHP** row has no **Restart** either.

## From the API {#from-the-api}

`GET /api/services` reads the list; `POST /api/services/<name>/restart` restarts `nginx`, `mariadb`
or `redis`. The restart of a service that is not installed is refused, and nothing is started, with
**409** `<name> is not installed on this server`; that of a disabled service with **409** too. Every
restart lands in the **Audit log**.
