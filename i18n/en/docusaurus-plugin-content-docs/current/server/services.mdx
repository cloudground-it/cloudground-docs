The **Services** page, in the **Server** group, lists the system services that run your sites:

| Row | System service |
| --- | --- |
| `nginx` | `nginx` |
| `mariadb` | `mariadb` |
| `redis` | `redis-server`, only where it's installed |
| **Site PHP** | every `cloudground-php-*.service`, one per site |

Each row shows **State**, **At boot** (*yes* or *no*), **Memory**, **Started** and **Version**. The
**Site PHP** row summarizes the PHP processes: how many are running and, if any aren't, which ones.

Services that aren't installed have no row. New servers don't get Redis (the sites' object cache
uses APCu), so there's no `redis` row. Servers upgraded from an earlier version keep Redis switched
off, and the row shows **disabled**. The `nginx` and `mariadb` rows are always present.

## Service states {#read-the-state}

| State | Meaning |
| --- | --- |
| **running** | The service is running. |
| **failed** | The service stopped with an error. |
| **disabled** | The service is intentionally off and doesn't start at boot. |
| **stopped** | The service isn't running, but it should be. |

A **failed** or **stopped** service raises an alert on the dashboard. See
[alerts and notifications](./alerts-and-notifications.mdx).

## Helper units {#helper-units}

*Since v0.3.0.* For backups, database dumps and certificates, the agent doesn't run `restic`,
`mariadb-dump`, the `mariadb` client or `certbot` inside its own process. Each one runs in a transient
`cg-helper-<tool>-<n>.service` unit, in the `cg-helper.slice` slice, with the agent's sandbox and its
own memory cap of 75% of the server's memory. If a tool exceeds the cap, the kernel kills it. That
operation (a backup, for example) fails, but the panel and the agent keep running. On startup the
agent stops any units left over from a previous run.

The `cloudground-agent.service` unit has its own memory limit: above 768 MB the kernel throttles it,
and above 1 GB it kills the process that went over. Transient units only show up in
`systemctl list-units 'cg-helper-*'` while they're working. For why they live outside the agent's
unit, see [the architecture](/docs/explanation/architecture#the-agent).

## Restart a service {#restart}

1. Open **Services**.
2. Click **Restart** on the service's row.
3. Confirm.

A restart interrupts in-flight requests for a few seconds. The panel waits up to 3 minutes for the
system to finish, since MariaDB can be slow to come back.

**Disabled** services have no **Restart** button. They're off on purpose (Redis, on an upgraded
server), and restarting would turn them on. The **Site PHP** row has no **Restart** button either.

## From the API {#from-the-api}

`GET /api/services` returns the list. `POST /api/services/<name>/restart` restarts `nginx`, `mariadb`
or `redis`. Restarting a service that isn't installed is refused with **409**
`<name> is not installed on this server`, and nothing is started. Restarting a disabled service also
returns **409**. Every restart is recorded in the **Audit log**.
