Every change to the code is a release. The next request uses the new one. There's nothing to restart: every run starts from scratch.

## Deploy a change {#deploy}

1. Open the function and go to the **Code** tab.
2. Edit the files. Until you deploy, the panel marks the code **Not deployed**.
3. Press **Deploy**.

**Discard changes** discards what you typed and puts back the code of the live release.

If the function has a `package.json` or a `requirements.txt`, its dependencies are installed before
the release goes live. If the install fails, the panel says *Deploy failed* with the output of that
step, and the previous release stays live.

Changing **Settings** or **Addresses** doesn't make a release.

## Roll back {#roll-back}

1. Open the function and go to the **Releases** tab. The release in use is marked **Live**.
2. On the row of the release you want, press **Roll back** and confirm.

The next call runs that code, with the dependencies it was deployed with. The latest 10 releases are
kept, along with the live one: an older release can't be recovered.
