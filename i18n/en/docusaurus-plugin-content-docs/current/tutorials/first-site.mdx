You put a WordPress site online at `<domain>`, see the page cache in action and take
your first backup. `<domain>` is the domain you pointed at the server, such as
`blog.example.com`.

## Set the certificate email {#set-the-certificate-email}

Once an email is set, the panel requests a certificate for each new site as soon as it creates it.

1. Open **Settings**.
2. In the **Certificates** card, enter an address in **Let's Encrypt email**.
3. Press **Save**.

## Create the site {#create-the-site}

1. Open **Sites** and press **New site**. The **New site** dialog opens.
2. In **Domain**, enter `<domain>`.
3. Leave **Type** set to **WordPress**.
4. Leave **Performance profile** set to **Recommended (Balanced)**.
5. Fill in **Site title** and **Admin email**. Leave **Admin username** as `admin`.
6. In **Admin password**, choose a password with at least 12 characters. This is the password you
   use to sign in to WordPress.
7. Under **Database**, keep the name, user and password the panel suggests.
8. Press **Create site**.

The dialog turns into a summary of the site. The top shows each creation step as it runs: the panel
creates the system user and the database, installs WordPress, writes the nginx and PHP configuration
and requests the certificate. Below that you find the site and panel URLs, the WordPress user and the
database credentials.

9. Press **Download as .txt** and store the file somewhere safe. This is the only place the database
   password is shown.
10. Press **Close**.

The site shows up in the list with the status **provisioning**. Once setup finishes, the status
changes to **active**.

## Open the site {#open-the-site}

In the site list, click the site's name to open its page. Press **Visit ↗**. Your browser loads the
WordPress home page over HTTPS.

To get to the WordPress dashboard, go back to the site's page and press **Log in to WordPress**. The
panel signs you in to wp-admin without asking for a password.

## See the cache in action {#watch-the-cache}

From your own computer, request the home page twice and check the `X-CloudGround-Cache` header:

```bash
curl -sI https://<domain>/ | grep -i x-cloudground-cache
curl -sI https://<domain>/ | grep -i x-cloudground-cache
```

The first response says `MISS`: PHP built the page and it was stored in the cache. The second says
`HIT`: nginx served the page straight from disk and PHP never ran.

## Connect a backup repository {#connect-the-repository}

Backups are stored in a restic repository. Here you use a folder on the same server.

1. Open **Settings** and find the **Off-site backups (restic)** card.
2. In **Backup destination**, choose **This server (a local folder)**.
3. In **Folder**, enter `/var/backups/cloudground`.
4. Next to **Repository password**, press **Generate**, then **Download**. Keep the file somewhere
   other than this server. If you lose the password, you lose the backups.
5. Press **Save**, then **Test connection**. The panel replies **Repository reachable: 0 snapshots**.

:::warning[For learning only]

A repository on the same server is lost along with the server. For real sites,
[connect an off-site repository](/docs/data/connect-a-backup-repository).

:::

## Take your first backup {#take-the-first-backup}

1. Open the site's page and go to the **Backups** tab.
2. Press **Back up now**.

The backup appears in the list with **Restore test** set to **pending**. As soon as the backup
completes, the panel restores it to a separate location and checks that the files and the database
actually come back. When the restore test is done, its status changes to **passed** and
**Estimated restore time** shows how long a real restore would take.
