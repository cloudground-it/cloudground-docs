In this tutorial you install CloudGround on a new server and create the administrator account. At
the end you open the panel in your browser.

:::warning[Use a dedicated server]

The installer takes over nginx, PHP, MariaDB, the firewall and the SSH configuration. Install it
only on a new server, or on one you can rebuild.

:::

## Copy the release to the server {#copy-the-release}

The repository is private, so there is no public download today. Build the release on your
computer, in the product's source folder:

```bash
make dist
```

Copy the `dist/` folder with the binaries and the `installer/` folder to the server, side by side:

```bash
ssh root@<server-ip> mkdir -p /root/cloudground
scp -r dist installer root@<server-ip>:/root/cloudground/
```

`<server-ip>` is the server's public address.

## Run the installer {#run-the-installer}

Sign in to the server as root and run the installer, pointing it at the local build:

```bash prompt
ssh root@<server-ip>
CLOUDGROUND_LOCAL_BUILD=/root/cloudground/dist bash /root/cloudground/installer/install.sh
```

It checks the machine first, then shows nine steps, each with its duration (below without the times,
which depend on the server):

```text
  ✓   1/9  Installing nginx, PHP, MariaDB, restic
  ✓   2/9  Creating users, directories and secrets
  ✓   3/9  Installing CloudGround binaries
  ✓   4/9  Tuning kernel and nginx workers
  ✓   5/9  Configuring nginx
  ✓   6/9  Tuning MariaDB
  ✓   7/9  Starting services
  ✓   8/9  Opening the firewall
  ✓   9/9  Log rotation and certificate renewal
```

If the machine check finds problems (system, architecture, memory, disk, ports in use), it lists them
all together and stops without touching anything. Fix them and run the same command again.

## Open the setup link {#open-the-setup-link}

At the end the installer prints an address like this one:

```text
  ✓  CloudGround is running

     Open   https://<server-ip>:8443/setup/<token>

     The link is valid for 24 hours and works once.
     Your browser will warn about the certificate — it is self-signed
     until you issue a real one. That is expected on first boot.
```

Open the link in your browser. The browser warns that the certificate is not valid: it is
self-signed, which is expected on first boot. Accept the warning for this address.

## Create the administrator account {#create-the-administrator}

The **First sign-in** page asks for an email and a password.

1. **First name** and **Last name** are optional.
1. Type your email.
1. Choose a password of at least 12 characters and repeat it in **Confirm password**.
1. Press **Create account**.

The panel creates the first administrator and signs you in. You see the dashboard, with no sites yet.

## Check that it runs {#check-it-runs}

On the server, check the panel's two services:

```bash prompt
systemctl is-active cloudground-agent cloudground-api
```

Both lines say `active`.
