This tutorial walks you through installing CloudGround on a new server and creating the
administrator account. By the end, you have the panel open in your browser.

:::warning[Use a dedicated server]

The installer takes over nginx, PHP, MariaDB and the SSH configuration. Only run it on a new server,
or on one you can rebuild from scratch.

:::

## Run the installer {#run-the-installer}

Connect to the server as root:

```bash
ssh root@<server-ip>
```

Replace `<server-ip>` with the server's public IP address. Then run the installer:

```bash prompt
curl -fsSL https://get.cloudground.it | bash
```

:::note[Installer URL]

The same script is also available at `https://cloudground-it.github.io/cloudground/install.sh`.
That is the GitHub Pages address behind `get.cloudground.it`.

:::

The script installs CloudGround v0.3.2. It downloads the release from GitHub and only runs the
bundled `cgctl` if its SHA-256 matches the one pinned in the script. `cgctl` in turn refuses to
install anything whose signed manifest fails verification. To check the script itself before you
run it, see [Verify the installer](/docs/server/verify-the-installer).

The installer checks the machine first, then runs nine steps and prints how long each one took. The
output below leaves out the timings, since they vary by server:

```text
  ✓   1/9  Installing nginx, PHP, MariaDB, restic
  ✓   2/9  Creating users, directories and secrets
  ✓   3/9  Installing CloudGround binaries
  ✓   4/9  Tuning kernel and nginx workers
  ✓   5/9  Configuring nginx
  ✓   6/9  Tuning MariaDB
  ✓   7/9  Starting services
  ✓   8/9  Opening the firewall
  ✓   9/9  Log rotation and certificate renewal
```

If the pre-flight check finds problems (OS, architecture, memory, disk space, ports already in use),
it reports all of them at once and exits without changing anything. Fix them and run the same
command again.

## Open the setup link {#open-the-setup-link}

When it finishes, the installer prints a URL like this:

```text
  ✓  CloudGround is running

     Open   https://<server-ip>:8443/setup/<token>

     The link is valid for 24 hours and works once.
     Your browser will warn about the certificate — it is self-signed
     until you issue a real one. That is expected on first boot.
```

If the server's firewall (ufw) is disabled, you also see two extra lines. The installer does not
enable ufw for you. Instead, it prints the commands that would enable it with SSH, the sites and the
panel allowed through. You can ignore them for now. The [firewall](/docs/access/firewall#enable)
page covers them.

Open the link in your browser. You get a certificate warning because the certificate is self-signed.
That is expected on first boot, so accept the warning for this address.

## Create the administrator account {#create-the-administrator}

The **First sign-in** page asks for an email address and a password.

1. **First name** and **Last name** are optional.
1. Enter your email address.
1. Choose a password with at least 12 characters and enter it again in **Confirm password**.
1. Press **Create account**.

The panel creates the first administrator account and signs you in. The dashboard opens, empty for
now.

## Check that the panel is running {#check-it-runs}

On the server, check the panel's two services:

```bash prompt
systemctl is-active cloudground-agent cloudground-api
```

You should see `active` on both lines.
