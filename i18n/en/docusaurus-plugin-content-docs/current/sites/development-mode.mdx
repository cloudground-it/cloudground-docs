With the page cache on, you and your visitors get a stored copy of a page, which gets in the way while you edit code or
templates. Development mode serves every request fresh for a set time, then
puts the cache back.

## Turn it on {#turn-on}

1. Open the site and go to the **Cache** tab.
2. In the **Development mode** card, click **15 minutes**, **30 minutes** or **60 minutes**.

The card then says that the page cache is bypassed until a time. Click the same button again while
it runs to start the time over.

## Turn it off {#turn-off}

Click **End now**, or wait. When the time is up, the panel puts the cache back, empties it
(so no page from before your work is served again) and warms it in the background. If putting
the cache back fails, the site stays in development mode and the panel tries again a minute later.

## Good to know {#notes}

- A static site, a proxy and a site whose page cache is off have nothing to bypass: the card says so.
- A [staging copy](/docs/data/staging-and-safe-push) never starts in development mode, even if production is in it.
- Only the page cache is bypassed. Other settings do not change, and a PHP site's own object cache
  is a separate setting.

## With cgctl {#cgctl}

```bash
cgctl devmode <site-id> 30
cgctl devmode <site-id> off
```

The length is `15`, `30` or `60`; `off` ends the mode now.
