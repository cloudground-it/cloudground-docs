A function is a small piece of code, such as a webhook, a form handler or a scheduled job, that
runs without a whole app. Each function belongs to a site and answers at
`https://<domain>/.functions/<name>`, and at every path below that address.

Nothing runs between requests. Each request starts a process of its own, under the site's user and
inside the site's sandbox and limits. The process exits as soon as it has answered. The server
enforces each invocation's memory and time limits.

## Create a function {#create}

1. Open the site. Under the **⋯** menu of the tabs, choose **Functions**.
2. Press **New function**, enter a name (lower-case letters, digits and `-`), pick **Node.js** or
   **Python**, and press **Create**.

The new function starts with code that echoes the request back as JSON. Its address is shown
above the editor.

The server must have the runtime version installed. Node.js 20, 22 and 24 and the server's own
Python can be installed under **Services** → **Runtimes**.

## Write the handler {#handler}

The code is a single file that exports a `handler` function, plain or async:

```js title="Node.js — index.js"
exports.handler = async (event) => {
  return { statusCode: 200, headers: { "Content-Type": "application/json" }, body: { ok: true } };
};
```

```python title="Python — main.py"
def handler(event):
    return {"statusCode": 200, "body": {"ok": True}}
```

`event` has `method`, `path` (the part after `/.functions/<name>`), `query`, `headers` (names in
lower case), `body` (text, or base64 with `isBase64Encoded`) and `source` (`http`, `schedule` or
`test`).

The handler returns either an object with `statusCode`, `headers` and `body`, or any other value. A
string is sent as plain text and anything else as JSON. If the handler throws, the request gets a
500 and the error goes to the function's output.

Only the runtime's standard library is available. A function doesn't install packages.

## Settings {#settings}

- **Runtime**: the Node.js or Python version.
- **Memory**: 64 to 1024 MB (128 by default). An invocation that uses more is stopped.
- **Timeout**: 1 to 300 seconds (10 by default). An invocation that runs longer is stopped, even
  one stuck in a loop.
- **Schedule**: five cron fields, such as `*/15 * * * *`, in the panel's time zone. Leave it
  empty to run only on request.
- **Variables** and **Secrets**: environment variables, as for a
  [Node.js or Python site](/docs/sites/node-and-python-sites#settings). Secrets are stored
  encrypted and never shown again.

## Deploy, test, roll back {#deploy}

**Deploy** saves the settings and, if you changed the code, makes it a new release. The next request
runs the new code. **Roll back** puts the previous release back. The ten newest releases are kept.

**Test** runs the function once through the same address and shows the status, the time it took and
the start of the answer.

## Invocations and output {#logs}

The **Invocations** card lists the latest requests from the site's access log, with their source,
status and duration. A 502 means the invocation crashed, ran past its timeout or went over its
memory. **Output** shows what the handlers printed and their errors.

## Use the API {#with-the-api}

- `GET` and `POST /api/sites/<id>/functions`
- `GET`, `PUT` and `DELETE /api/sites/<id>/functions/<name>`
- `POST /api/sites/<id>/functions/<name>/rollback`, `.../invoke`, and `GET .../logs`
