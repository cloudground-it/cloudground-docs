A site responds to its domain and to any aliases you add. You set the domain when you create the site
and can't change it later. Aliases you can add or remove at any time. The certificate covers both the
domain and the aliases.

## Set the Let's Encrypt email {#set-the-acme-email}

You only do this once per server:

1. Open **Settings**.
2. Under **Certificates**, enter the **Let's Encrypt email**. It's used for the account registration
   and for expiry notices.
3. Save.

Without this email, the panel can't issue or renew certificates.

## Issue a certificate {#issue-the-certificate}

1. Open the site and go to its **SSL** tab.
2. Choose **Issue / renew**.

The panel starts a **Certificate** task. Before requesting the certificate, the server checks that
every name actually resolves to it: it writes a test file and fetches it from
`http://<name>/.well-known/acme-challenge/`. If a name doesn't respond, the task fails without using up
a Let's Encrypt attempt, and tells you where that name's DNS points.

The **Current certificate** box shows the issuer and the expiry date. The panel renews Let's Encrypt
certificates automatically when 30 days are left. If a renewal fails, the box shows
**Last renewal failed** and the reason.

## Issue a wildcard certificate {#a-wildcard-certificate}

A wildcard certificate covers `<domain>` and `*.<domain>`. It's validated through Cloudflare DNS
instead of the test file.

1. In **Settings**, under **Certificates**, enter the **Cloudflare API token**. The token needs the
   Zone:DNS:Edit permission.
2. On the site's **SSL** tab, choose **Wildcard**.

A wildcard certificate doesn't include the aliases. It covers only the domain and its subdomains.

## Install your own certificate {#your-own-certificate}

1. On the **SSL** tab, under **Custom certificate**, paste the **Full chain (PEM)** and the
   **Private key (PEM)**.
2. Choose **Install**.

The server rejects a certificate that doesn't match the key, doesn't cover the domain or has already
expired. A custom certificate takes priority over the Let's Encrypt one, and the panel doesn't renew
it. To switch back to Let's Encrypt, choose **Back to Let's Encrypt**.

## Add an alias {#add-an-alias}

Only administrators can change aliases.

1. Open the site, go to the **Overview** tab and find the **Domains and folder** card.
2. In **Aliases**, type each name and press Enter. Click the × on a name to remove it.
3. Choose **Apply**.

Through the API, send the complete list. An empty list, `[]`, removes all aliases:

```bash
curl --unix-socket /run/cloudground/api.sock http://localhost/api/sites/<id> \
  -X PATCH \
  -H "Authorization: Bearer $CLOUDGROUND_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"aliases": ["www.example.com"]}'
```

- Each alias must be a plain hostname, different from the site's domain. You can have up to 50.
- A name can belong to only one site. An alias already used by another site is rejected with `400`
  (`alias … is already used by …`) and nothing changes.
- If the site has a Let's Encrypt certificate, the panel automatically reissues it to include the new
  names. If the reissue fails, the site keeps serving the previous certificate.
- If the site has a custom certificate, the panel warns you that it might not cover the new aliases.
  Install one that does. If you choose **Back to Let's Encrypt** instead, the site goes back to its
  previous Let's Encrypt certificate. Then choose **Issue / renew** so the certificate covers the new
  aliases.
