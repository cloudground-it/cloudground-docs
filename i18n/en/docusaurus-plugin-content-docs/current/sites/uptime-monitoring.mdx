When uptime monitoring is on, the panel requests the site from its public address every minute, the
same way a visitor would. If the site stops responding, you get an alert.

Monitoring is off by default on every site, because a site whose domain doesn't point here yet
would look down.

## Turn on monitoring {#turn-it-on}

1. Open the site. The **Uptime** card is on the **Overview** tab.
2. In **Path to request**, enter a page that loads quickly. If you don't have a better one, keep `/`.
3. Press **Turn on**.

The first check runs immediately. The card shows the status (**answering**, **one failure**,
**down**), the **Address checked**, the **Last check** and the **Answer**, with the HTTP status code
and response time. While the site is down, it also shows **Down since**.

To change the path, enter a new one and press **Save**. To stop monitoring, press **Turn off**. Any
open alert is closed.

The path must start with `/` and contain only letters, digits and `. _ ~ -` between slashes. Query
strings aren't allowed.

## What counts as a response {#what-counts}

The panel sends `GET https://<domain><path>` with a 10-second timeout.

- **Answering**: any status code below 500, including 401 and 404.
- **Failure**: a 5xx status code, a refused or reset connection, a certificate a browser would
  reject, or no response within 10 seconds.

The panel doesn't follow redirects. A 3xx counts as a response, and the check stays on the
site's own address.

## Alerts {#the-alert}

Two failures in a row trigger an **Uptime** alert at error level, with the reason for the latest
failure. A single failure, such as a dropped packet or a reload, isn't enough. The alert appears in
the **Alerts** panel and goes to the alert webhook (see
[Alerts and notifications](/docs/server/alerts-and-notifications)). It closes automatically once the
site responds again.

Restarting the panel doesn't close or reopen an alert that's already open.

## Use the API {#with-the-api}

- `GET /api/sites/<id>/uptime` returns `enabled`, `path`, `url`, `interval_seconds` and `last`, the
  most recent check.
- `PUT /api/sites/<id>/uptime` with `{"enabled": true, "path": "/health"}` turns monitoring on or
  changes the path. `{"enabled": false}` turns it off.
