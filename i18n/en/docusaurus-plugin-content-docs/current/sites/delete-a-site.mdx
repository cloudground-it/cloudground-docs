:::danger[You can't undo this]

Deleting a site removes its files, its database and its staging copy. If you might need them, take a
backup first and make sure its restore test passed.

:::

## Delete a site in the panel {#from-the-panel}

1. Open the site.
2. Open the **More** menu (the three dots next to **Visit**) and choose **Delete**.
3. Type the site's domain to confirm, then choose **Delete**.

The site's status changes to **deleting** and a **Site deletion** task starts. When the task finishes,
the site disappears from the list. If you request deletion again while it's running, the new request
attaches to the task in progress.

With cgctl:

```bash
cgctl --wait sites delete <id>
```

## What gets removed {#what-goes}

The server removes these, in this order:

1. The vhost, the page cache zone and the staging password. The site stops responding.
2. Every process that belongs to the site: its PHP, running scheduled tasks and wp-cli commands.
3. The site's PHP service and its configuration.
4. The scheduled tasks.
5. The database and its user.
6. The Let's Encrypt certificate and any custom certificate.
7. The site's SSH shell, then its system user and group.
8. The page cache, the logs and the site's folder.

The server runs every step even if one fails, then reports all errors together at the end. Running
the deletion again is safe, because each step only removes what's still there.

The panel also drops the site's releases, backups, scheduled tasks and operator assignments.

:::note[Snapshots stay in the repository]

Deleting a site doesn't touch the restic repository. The site's snapshots remain there, but the panel
no longer lists them and can't restore them. To free the space, remove them yourself with restic. On
the server, as root:

```bash prompt
export RESTIC_REPOSITORY=<repository> RESTIC_PASSWORD_FILE=<password-file>
restic snapshots --tag site:<domain>
restic forget --prune <id> <id>
```

`<repository>` is the **Repository** value in **Settings**, `<domain>` is the deleted site's domain and
each `<id>` is a snapshot ID from the first command's output. For an S3 repository, also export
`AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.

:::

## If deletion fails {#if-it-fails}

The site stays in the list with the status **error**, and the task names the step that failed. Fix the
cause and choose **Delete** again.

Deleting a production site deletes its staging copy first. If you cancel the task between the two,
production stays and returns to its previous status.
