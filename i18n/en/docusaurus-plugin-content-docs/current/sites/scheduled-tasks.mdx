A scheduled task is a command that runs for a site on a cron schedule. It runs as the site's user,
inside the site's folder, with the same sandboxing as the site's PHP.

## Add a task {#add-a-task}

1. Open the site, then choose **More** and **Cron**.
2. Under **New scheduled task**, enter a **Schedule (cron)** or choose one from **Presets**:
   **Every 5 minutes**, **Every 15 minutes**, **Hourly**, **Daily at 3am**, **Sundays at 3am**.
3. In **Command**, enter the command, such as `php current/artisan schedule:run`.
4. Optionally, use **Description** to note what the task does.
5. Choose **Add**.

The task runs with `PATH` set to `/usr/local/bin:/usr/bin:/bin`. That means `php` resolves to
`/usr/bin/php`, the server's default CLI, which isn't necessarily the site's PHP version. If the site
uses a different version, call it explicitly, for example `php8.4 current/artisan schedule:run`.

The command starts in the site's folder (`/srv/sites/<domain>`), which is also its `HOME`. Its output,
including errors, goes to `logs/cron-<id>.log` in the site's folder, which keeps the last 500 lines.
If a scheduled run lasts longer than 6 hours, it's stopped along with every process it started.

WordPress and WooCommerce sites already have WordPress's own cron running from the system every 5
minutes, so you don't need to add it.

## Schedule syntax {#the-schedule}

A schedule has five space-separated fields: minute (0–59), hour (0–23), day of month (1–31), month
(1–12) and day of week (0–7). Each field can be `*`, a number `N`, a range `N-M` or a comma-separated
list. `*` and ranges accept a step, as in `*/15` or `0-30/10`.

The panel rejects names (`mon`, `jan`), shortcuts such as `@daily` and the `N/S` form. It also rejects
a command that makes the cron line longer than 998 bytes, and tells you how many bytes to remove.

## Run a task now {#run-now}

Choose **Run now** next to the task. The command runs once, for up to 300 seconds, and a window shows
its status and output (the last 64 KiB). If the task is already running, the panel won't start
another run.

## Pause, edit or remove a task {#pause-edit-remove}

- Turn off the **Run on schedule** switch to pause the task. It stays in the list but stops running.
- **Edit task** (the pencil icon) loads the task back into the form. Choose **Save** when you're done.
- **Remove** (the bin icon) deletes the task after you confirm.

With cgctl, you can run a task by its ID: `cgctl cron run <id>`.

## Who can see the command {#who-sees-the-command}

*Since v0.2.0.* A command line can contain a token or a password. Administrators and operators see the
full command. Read-only accounts see the tasks, their schedules and their last runs, but only a
shortened form of the command, the same one the **Audit log** uses: the first word, the number of
words and a short fingerprint, for example `php … (3 words, sha256:1a2b3c4d)`.
