A WordPress database collects expired transients and a revision of a post
for every save. The weekly cleanup removes them and leaves the rest alone. It is off by default.

## What it does {#what}

- It deletes the **expired transients**.
- It trims the revisions so that each post keeps only its newest **N**, a number from 1 to 100 (5
  until you change it).
- It measures the **autoloaded options**, the ones WordPress loads on every request, and lists the
  largest. It does not change them.

## Look before you clean {#dry-run}

1. Open the site and go to the **WordPress** tab.
2. In the **Database cleanup** card, click **Dry run**.

The card lists what a cleanup would delete: the expired transients, the revisions beyond the newest
N of each post, and the number and size of the autoloaded options. Nothing changes.

## Turn it on {#turn-on}

1. In the same card, set **Revisions kept per post** and click **Save**.
2. Turn on **Clean every week**.

Without a backup repository the panel refuses to turn it on
([Connect a backup repository](/docs/data/connect-a-backup-repository)), because the first cleanup of a site
takes a snapshot. Turning it on does not clean at once. Each site has a slot of its own in the week;
the card shows the **Next cleanup**, and the **Last cleanup** once there is one.

To clean right now, click **Clean now**.

## The first cleanup {#first-run}

Before it deletes anything for the first time, the panel takes a snapshot and
[restores it as a test](/docs/data/run-a-restore-test). If the test fails, the cleanup stops and
nothing is deleted. Later cleanups skip the snapshot. Each run starts with a dry run, which goes to
the task's log.

## Read the result {#log}

Each cleanup adds its counts to the site's cleanup log: open the site's **Logs** tab and choose
**Cleanup**. A cleanup that fails raises an [alert](/docs/server/alerts-and-notifications) like any
other task.

## With cgctl {#cgctl}

```bash
cgctl cleanup <site-id> on 5      # weekly, keep 5 revisions per post (the number is optional)
cgctl cleanup <site-id> preview   # the dry run
cgctl --wait cleanup <site-id> run
cgctl cleanup <site-id> off
```
