Every new site gets its own system user, folder and vhost. All types except static and reverse proxy
also get their own PHP. WordPress, WooCommerce and Laravel sites get a database as well. Only
administrators can create sites.

## Create a site in the panel {#from-the-panel}

1. Open **Sites** and choose **New site**.
2. In **Domain**, enter the site's domain, such as `example.com`. The panel converts it to lowercase.
3. In **Type**, choose the kind of site. The [site types reference](/docs/reference/site-types)
   explains how they differ.
4. In **PHP**, keep **Default version** or choose another version installed on the server. Static and
   reverse proxy sites don't have this field.
5. In **Performance profile**, keep **Recommended** or choose **Balanced**, **Commerce** or
   **Maximum**.
6. Fill in the fields for the type you chose:
   - **WordPress** and **WooCommerce**, under **WordPress administrator**: **Site title** (optional;
     defaults to the domain), **Admin email**, **Admin username** and **Admin password**, which needs
     at least 12 characters (press **Generate** to create one). You use these to sign in to WordPress.
   - **Reverse proxy**: **Upstream URL**, such as `http://127.0.0.1:3000`. It must be an `http` or
     `https` URL without credentials, a query string or a fragment.
7. Fill in the **Database** section (see below).
8. Read the line at the bottom, which lists what the site will get, then choose **Create site**.

## Set up the database {#database}

What the **Database** section offers depends on the site type:

- **WordPress**, **WooCommerce** and **Laravel** always get a database, because their configuration
  depends on it.
- **PHP** and **Static**: turn on **Create a database too** to get a MariaDB database plus a user with
  full privileges on it. If you leave it off, the site starts without one. You can add one later from
  the [Database tab](/docs/data/manage-databases).
- **Reverse proxy**: no database.

If the site gets a database, fill in:

1. **Database name** and **Database user**. The panel suggests a name based on the domain
   (`blog.example.com` becomes `blog_example`) and uses it for both until you change either one.
2. **Database password**. The panel pre-fills a generated password. Keep it, press **Generate** for a
   new one, or type your own. Press **Show** to reveal it.

Names and passwords must follow the [database rules](/docs/reference/database-names-and-passwords).
For example, the panel rejects a name that is already taken on this server, or a password that
contains `'`, `"` or `\`, and shows the error under the field.

## Save the summary {#summary}

After you press **Create site**, the dialog turns into a summary of the site. The top lists each
creation step as it runs, marked *done*, *in progress* or *failed*. Below that is everything you need
to start using the site:

| Section | Rows |
| --- | --- |
| **Site** | **Site URL**, **In the panel** |
| **WordPress** | **Admin URL**, **Admin user** |
| **Database** | **Host**, **Port**, **Socket**, **Database name**, **Database user**, **Database password** |
| **SFTP** | off, with the site's system user you need to turn it on |

:::warning[You only see the database password here]

The summary is the only place the panel ever shows the database password, whether you chose it or
the panel generated it. Before you close the dialog, press **Download as .txt** or **Copy**. If you
lose the password, set a new one from the [Database tab](/docs/data/manage-databases#reset-password).

:::

- **Download as .txt** saves the full summary as `<domain>-cloudground.txt`. The file contains
  passwords, so keep it somewhere safe and delete it once you've stored them elsewhere.
- **Copy** puts the same text on your clipboard.
- **Close** asks *Close without saving?* if you haven't used either option. Leaving or reloading the
  page asks too.
- **Open the site** takes you to the site's page.

The site appears in the list as **provisioning**. When the **Site creation** task finishes, the
status changes to **active**.

If **Let's Encrypt email** is set in the panel's **Settings**, creating the site also requests a
certificate. If DNS doesn't point at the server yet, the site is still created. The task notes this
in its messages (`Certificate pending (DNS may not point here yet)`), and until you issue a
certificate from the **SSL** tab, the site serves the server's self-signed fallback certificate
(`CN=fallback.invalid`), which browsers reject.

## SFTP is off by default {#sftp}

SFTP access starts out disabled on a new site. Nobody can connect over SFTP until you enable it, with
its own password, from the site's **SFTP / SSH** tab. See [SFTP and SSH keys](/docs/access/sftp-and-ssh-keys).

## Create a site with cgctl {#with-cgctl}

```bash
cgctl --wait sites create example.com wordpress \
  '{"admin_email":"you@example.com","admin_user":"admin","admin_password":"<password>","title":"My site"}'
```

- `<password>` is the WordPress administrator password, at least 12 characters long.
- The third argument is a JSON object with the optional fields: `profile`, `php_version`,
  `cache_enabled`, `object_cache`, `aliases`, and `proxy_upstream` for reverse proxy sites.
- `--wait` blocks until the task finishes and exits with 0 only if it succeeded.

Database options:

| Option | Effect |
| --- | --- |
| `--with-database` | Also creates a database for a `php` or `static` site. |
| `--db-name <name>` | Database name. Defaults to `site_<id>`. |
| `--db-user <name>` | Database user name. Defaults to `site_<id>`. |
| `--db-password-stdin` | Reads the password from a single line on standard input. |
| `--db-password-file <file>` | Reads the password from a file. |
| `--db-password <password>` | Takes the password on the command line. cgctl warns you that it shows up in `ps` and your shell history. Use one of the two options above instead. |
| `--json` | Prints the raw JSON response from the API instead of the summary. |

If you don't give a password, the panel generates one. For example, to create a Laravel site with
the password in a file only root can read:

```bash prompt
cgctl --wait sites create shop.example.com laravel \
  --db-name shop --db-user shop_app --db-password-file /root/shop-db.pass
```

cgctl prints the same summary as the panel, and only once:

```text
shop.example.com (laravel, site 7)
Created.

Site
  URL:         https://shop.example.com/
  Panel:       /sites/7

Database
  Host:        127.0.0.1
  Port:        3306
  Socket:      /run/mysqld/mysqld.sock
  Name:        shop
  User:        shop_app
  Password:    <password>

SFTP
  Off: turn it on from the site's SFTP tab (user cg-site-7).

The database password is shown only now: keep it safe. A new one can be set from the site's Database tab.
```

When you connect through the server's local socket, the panel link is just a path. Over `https://`
it's a full URL. For a reverse proxy site:

```bash
cgctl --wait sites create app.example.com proxy '{"proxy_upstream":"http://127.0.0.1:3000"}'
```

## Troubleshooting {#if-it-fails}

- **Domain already in use**: another site already uses it as its domain or as an alias. The request
  is rejected before anything is created.
- **Database or user name already taken** on this server, or invalid: the request is rejected before
  anything is created, and the error names the field.
- **PHP version not installed**: choose one of the versions listed under **PHP**.
- **A creation step fails**: the server rolls back the steps it already completed and the site
  disappears from the list. The task message names the step that failed.
- **The panel loses contact with the server mid-creation**: the site stays in the list with the
  status **error**. Delete it and create it again.
