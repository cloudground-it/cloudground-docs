On WordPress and WooCommerce you'll rarely need this. The connector purges the pages affected by a
change on its own (see the list in the [cache reference](/docs/reference/cache-behaviour#automatic-purges)).
Purge by hand when you change something the panel can't see, such as a theme file uploaded over
SFTP, or when the site runs plain PHP or Laravel.

## Purge a single URL {#purge-one-url}

1. Open the site and go to the **Cache** tab.
2. In the **Purge the cache** card, enter the full URL under **Purge one URL**, for example
   `https://<domain>/blog/post/`.
3. Click **Purge**.

The panel confirms with **URL purged**. Both `GET` and `HEAD` entries are removed, over HTTP and
HTTPS, for the site's domain and all its aliases.

## Purge the whole site {#purge-everything}

In the **Cache** tab, click **Purge everything**. The panel confirms with **Cache purged**.

You'll find the same **Purge the cache** command under **Actions** in the site's **Overview** tab,
and in each site's menu in the site list.

## With cgctl {#with-cgctl}

```bash prompt
cgctl purge <site-id>                               # the whole site
cgctl purge <site-id> https://<domain>/blog/post/   # one or more addresses
```

`<site-id>` is the site's number, as shown by `cgctl sites list`. The `removed` field in the output
says how many entries were cleared. To set up cgctl, see [API tokens and cgctl](/docs/access/api-tokens-and-cgctl).

## Warm the cache {#warm-the-cache}

After a full purge, the first visitor to each page gets an uncached response. To refill the cache
right away from the site's sitemap, go to the **Overview** tab and click **Warm the cache** under
**Actions**. On WordPress you can also use the **Warm now** button in the **Cache warming** card of
the **WordPress** tab.

With cgctl, run `cgctl warm <site-id>`. The panel warms the cache automatically after activating a
release, publishing from staging, and migrating a site. After a rollback it purges the cache but
doesn't warm it.

## Check the result {#check}

```bash
curl -sI https://<domain>/blog/post/ | grep -i x-cloudground-cache
```

Right after the purge the header reads `MISS`. The next request reads `HIT`.

## A site behind Cloudflare {#cloudflare}

If the site is proxied by Cloudflare, Cloudflare may keep its own copy of the pages. Once you've set
the site's Zone ID and a Cloudflare purge token, every purge above empties that copy too. See
[run a site behind Cloudflare](/docs/sites/behind-cloudflare#cdn-purge).
