A restore replaces the production site with the contents of a snapshot. Before it touches
anything, the panel takes a new backup of the site and checks it: if that backup fails its restore
test, the restore stops and the site stays as it was.

:::danger[A restore replaces the current data]

Whatever changed on the site after the snapshot disappears from the site. It survives only in the
safety snapshot taken at the start of the restore.

:::

## Restore from the panel {#restore}

1. Open the site and choose the **Backups** tab.
2. Pick a snapshot whose test *passed* and press **Restore** on its row.
3. In **What to restore** choose:
   - **Everything (files and database)**;
   - **Files only**;
   - **Database only**.
4. With *Everything* or *Database only*, in **Databases to restore** leave checked the databases to
   bring back (see [below](#databases)).
5. Press **Continue**, type the site's domain to confirm, and press **Restore**.
6. Follow the task *Restore started* to its end.

The safety snapshot appears in the list of backups: if you need to go back, restore that one.

## What changes on the site {#what-changes}

- **Files**: the site folder is swapped for the snapshot's in one step, with no moment where the
  site has no files. Then the site's PHP restarts and nginx reloads its configuration. If the site
  does not come back, the panel puts the previous folder back.
- **Databases**: each database the backup holds is emptied and recreated from its dump. Tables
  created after the snapshot do not stay. If one import fails, that database and every one restored
  before it go back to what they were.
- At the end the site's page cache is emptied. With *Database only*, the object cache is flushed
  too, so the site does not serve stale data.

## Which databases {#databases}

*Since v0.2.0.* With *Everything* and *Database only* you choose which of the backup's databases to
restore. The restore dialog lists, in **Databases to restore**, the databases the snapshot holds, all
checked.

- Leave them all checked to restore them all.
- Uncheck the ones not to touch: only the checked databases are replaced, the others keep what they
  hold now.
- With no database checked **Continue** stays disabled: choose at least one, or restore **Files
  only**.

A backup taken before v0.2.0 does not record its databases: for it the dialog lists the databases the
site has now, and the restore puts back the ones the snapshot really holds.

These rules also apply:

- A database the backup holds and the site no longer has is skipped, and the task names it. To
  restore it, create it again with the same name in the [Database tab](/docs/data/manage-databases), then
  restore.
- A database created after the backup is not in the snapshot and stays as it is. If you name it with
  the API or cgctl, the restore is refused.
- A site with no database cannot take a *Database only* restore.

With the API, the list `GET /api/sites/<site-id>/backups` gives each backup a `databases` field: the
names of the snapshot's databases, `[]` when it has none, `null` for a backup taken before v0.2.0. To
restore only some, `POST /api/backups/<backup-id>/restore` with
`{"confirm": "<domain>", "mode": "database", "databases": ["shop_data"]}`. Each name must be a
database of the site; a name the snapshot does not hold gets **400**
`snapshot <id> holds no database "<name>"`, before anything starts. With `"mode": "files"` no
database can be named.

## From the command line {#cli}

```bash
cgctl --wait backup restore <backup-id> <domain> files
cgctl --wait backup restore <backup-id> <domain> database --database shop_data
```

`<backup-id>` is the `id` field of a backup in the list `GET /api/sites/<site-id>/backups`;
`<domain>` is the site's domain, as confirmation. The word after the domain is `full` (the value when
you leave it out), `files` or `database`.

*Since v0.2.0.* `--database <name>` restores only that database of the snapshot. Repeat it for each
database to restore; the form `--database=<name>` works too, anywhere after `backup restore`. Without
`--database` the restore puts back every database.
