A restore replaces the production site with the contents of a snapshot. Before it changes anything,
the panel takes a fresh backup of the site and tests it. If that backup fails its restore test, the
restore stops and the site is left untouched.

:::danger[A restore replaces the current data]

Anything that changed on the site since the snapshot is gone from the site. The only copy left is in
the safety snapshot taken at the start of the restore.

:::

## Restore from the panel {#restore}

1. Open the site and go to the **Backups** tab.
2. Find a snapshot whose test *passed* and click **Restore** on its row.
3. Under **What to restore**, choose one of:
   - **Everything (files and database)**
   - **Files only**
   - **Database only**
4. For *Everything* or *Database only*, leave checked the databases you want back under **Databases
   to restore** (see [below](#databases)).
5. Click **Continue**, type the site's domain to confirm, and click **Restore**.
6. Follow the *Restore started* task until it finishes.

The safety snapshot appears in the backup list. To undo the restore, restore that snapshot.

## What happens to the site {#what-changes}

- **Files**: the site folder is swapped for the snapshot's copy in a single step, so the site is
  never without files. The site's PHP then restarts and nginx reloads its configuration. If the site
  doesn't come back up, the panel puts the previous folder back.
- **Databases**: each database in the backup is emptied and rebuilt from its dump. Tables created
  after the snapshot are dropped. If one import fails, that database and every database restored
  before it are rolled back.
- When the restore finishes, the site's page cache is cleared. With *Database only*, the object
  cache is flushed too, so the site doesn't serve stale data.

## Choose which databases to restore {#databases}

*Since v0.2.0.* With *Everything* and *Database only*, you pick which databases from the backup to
restore. **Databases to restore** in the restore dialog lists every database in the snapshot, all
checked.

- Leave them all checked to restore them all.
- Uncheck any you want to leave alone. Only checked databases are replaced. The others keep their
  current data.
- If no database is checked, **Continue** stays disabled. Check at least one, or choose **Files
  only**.

Backups taken before v0.2.0 don't record their databases. For those, the dialog lists the site's
current databases, and the restore brings back the ones the snapshot actually contains.

A few more rules:

- If the backup holds a database the site no longer has, it's skipped and the task names it. To
  restore it, recreate it with the same name in the [Database tab](/docs/data/manage-databases), then
  run the restore again.
- A database created after the backup isn't in the snapshot and is left as it is. Naming it through
  the API or cgctl makes the restore fail.
- A site without databases can't do a *Database only* restore.

In the API, `GET /api/sites/<site-id>/backups` returns a `databases` field for each backup: the names
of the databases in the snapshot, `[]` if it has none, or `null` for backups taken before v0.2.0. To
restore only some of them, send `POST /api/backups/<backup-id>/restore` with
`{"confirm": "<domain>", "mode": "database", "databases": ["shop_data"]}`. Every name must be one of
the site's databases. A name the snapshot doesn't contain returns **400**
`snapshot <id> holds no database "<name>"` before anything starts. With `"mode": "files"` you can't
name any databases.

## Restore from the command line {#cli}

```bash
cgctl --wait backup restore <backup-id> <domain> files
cgctl --wait backup restore <backup-id> <domain> database --database shop_data
```

`<backup-id>` is a backup's `id` field from `GET /api/sites/<site-id>/backups`. `<domain>` is the
site's domain, which acts as confirmation. The word after the domain is `full` (the default if you
leave it out), `files` or `database`.

*Since v0.2.0.* `--database <name>` restores only that database from the snapshot. Repeat it once per
database. `--database=<name>` also works, anywhere after `backup restore`. Without `--database`,
every database is restored.
