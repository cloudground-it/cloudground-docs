The agent keeps its own record of which databases and database users belong to which site, in
`/var/lib/cloudground-agent/databases.json`. It refuses to touch any database or user that the record
doesn't assign to the site. If the file is deleted, moved or damaged, `panel-agent adopt-databases`
rebuilds it from the panel's records and from what exists in MariaDB. It never creates, drops or
grants anything.

## When you need this {#when}

- The **Database** tab or Quarry says *`"<name>"` is not a database of `<domain>`* for a database the
  tab lists. Without its file, the agent rebuilds the record from `site_<id>` names only, so every
  name you chose yourself is missing.
- Every database request fails with *the agent's record of the sites' databases is not available*,
  followed by the reason, for example that the file is damaged. The agent never overwrites a file it
  can't read.

## Stop the agent {#stop}

The running agent holds the record in memory and would overwrite the rebuilt file with its own copy.
As root:

```bash prompt
systemctl stop cloudground-agent
```

If the agent reported the file as damaged, move it out of the way first so the command starts from a
clean record:

```bash prompt
mv /var/lib/cloudground-agent/databases.json /var/lib/cloudground-agent/databases.json.damaged
```

## Preview the result {#dry-run}

```bash prompt
panel-agent adopt-databases --dry-run
```

The command reads the panel's records (read-only), lists the server's databases and `localhost`
users, and prints one line per name, followed by a summary:

```text
adopted database shop_data for site 3
kept database site_3 (site 3)
refused database old_data (site 3): the server has no database of that name
1 adopted, 1 already recorded, 1 refused
dry run: nothing was written
```

- **adopted**: the panel's records assign the name to the site, the server has it, and no other site
  claims it. A user's privileges are adopted with it, on the databases adopted for the same site.
- **kept**: the record already assigns the name to the same site.
- **refused**: shown with the reason. Reserved names, another site's `site_<n>`, names two sites
  claim, names the record assigns to another site, and names the server doesn't have are never
  adopted.

## Write the record and start the agent {#adopt}

```bash prompt
panel-agent adopt-databases
systemctl start cloudground-agent
```

Without `--dry-run`, the command writes the record. If it can't, it prints *the record was not
written* with the reason, and exits with 1.

- The command only runs as root, and refuses to run while the agent's socket responds: *the agent is
  running: stop it first*.
- The panel's records are read from `/var/lib/cloudground/state.db`. Use `--state <path>` to read a
  different file. A file from a panel too old to record custom names is refused, with instructions on
  what to do.
- The panel and the API can't trigger this command: it only runs on the server.
