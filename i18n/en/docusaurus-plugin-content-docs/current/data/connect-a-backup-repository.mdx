All sites store their backups in a single restic repository. Data is encrypted on the server with the
repository password before it leaves. You set both in **Settings**, in the **Off-site backups
(restic)** panel.

## Choose a destination {#destination}

1. Open **Settings** and find the **Off-site backups (restic)** panel.
2. Under **Backup destination**, choose where snapshots go.
3. Fill in the fields for that destination.

| Backup destination | Fields | Repository the panel saves |
| --- | --- | --- |
| **This server (a local folder)** | **Folder**, an absolute path such as `/var/backups/cloudground` | the folder |
| **Amazon S3** | **Region** (for example `eu-central-1`), **Bucket**, **Folder in the bucket** | `s3:https://s3.<region>.amazonaws.com/<bucket>[/<folder>]` |
| **Cloudflare R2** | **Account ID** (on the R2 page of the Cloudflare dashboard, under *Account details*), **Bucket**, **Folder in the bucket** | `s3:https://<account-id>.r2.cloudflarestorage.com/<bucket>[/<folder>]`, region `auto` |
| **Backblaze B2** | **Region** (for example `eu-central-003`), **Bucket**, **Folder in the bucket** | `s3:https://s3.<region>.backblazeb2.com/<bucket>[/<folder>]` |
| **Wasabi** | **Region** (for example `eu-central-1`), **Bucket**, **Folder in the bucket** | `s3:https://s3.<region>.wasabisys.com/<bucket>[/<folder>]` |
| **Hetzner Object Storage** | **Region**, which is the location (for example `fsn1`), **Bucket**, **Folder in the bucket** | `s3:https://<region>.your-objectstorage.com/<bucket>[/<folder>]` |
| **OVHcloud Object Storage** | **Region** (for example `gra`), **Bucket**, **Folder in the bucket** | `s3:https://s3.<region>.io.cloud.ovh.net/<bucket>[/<folder>]` |
| **MinIO or another S3-compatible service** | **Endpoint** (for example `https://minio.example.com`), **Region** (only if the service needs one), **Bucket**, **Folder in the bucket** | `s3:https://<endpoint>/<bucket>[/<folder>]` |
| **Other restic repository (advanced)** | **Repository**, in restic's own syntax, and an optional **Region** | exactly what you type |

- **Folder in the bucket** is optional. Use it when the bucket also holds other data, for example
  `cloudground`.
- **Bucket**: create it with your provider first. It can stay private.
- Every object storage destination also needs an **Access key** and a **Secret key**. Use a key that
  can read and write this bucket and nothing else. **Advanced** shows these fields too when the
  repository starts with `s3:`.
- Below the fields, **Repository** shows the address the panel will save, as restic reads it.

If a repository saved earlier doesn't match any of the destinations above exactly (an SFTP or REST
server, credentials in the address, a different path), it shows up as **Other restic repository
(advanced)** with its address unchanged.

:::warning[A folder on this server is not an off-site backup]

If you lose the server, you lose the backups with it. For an off-site backup, use object storage.

:::

- **SFTP** (advanced, `sftp:<user>@<host>:/<path>`, or `sftp://<user>@<host>:<port>//<path>` for
  another port): the panel signs in with a key of its own. Under **The panel's SSH key**, click
  **Make a key**, copy the public key and add it to `~/.ssh/authorized_keys` of that account on the
  SFTP server, then save. The private key is stored encrypted and never shown. The server's host key
  is recorded the first time, when the settings are saved and tested, and checked every time after.
  **Make a new key** replaces the key: backups stop reaching the server until you add the new one.
- **Backblaze B2**: the **Backblaze B2** destination uses B2's S3-compatible API. To use B2's own API
  instead, choose **Other restic repository (advanced)** with `b2:<bucket>:<path>` and fill in **B2
  key ID** and **B2 application key** with an application key limited to that bucket. Both are
  stored encrypted.

## Set the repository password {#password}

The repository password encrypts every snapshot. Without it no backup can be restored, not even by
the panel. Keep a copy somewhere other than this server.

1. Next to **Repository password**, click **Generate**. The panel creates a 32-character password and
   shows it.
2. Under **Keep this password safe**, click **Copy** or **Download**. **Download** saves
   `cloudground-backup-password.txt`, which holds the password and the repository.
3. Store it off this server.

You can type your own password instead of generating one. Once saved, the password is never
shown again, **Generate** disappears and the field reads **Set**. Only change the password when you
switch to a new, empty repository: existing snapshots open only with the old one.

## Save the settings {#save}

Click **Save**. When you change the repository or the password, the panel tests them together before saving. If the
repository doesn't exist yet, the panel creates it. If it exists and the password doesn't open it, the
panel refuses to save, because the existing backups would become unreadable.

### Passwords in the repository address {#password-in-the-address}

*Since v0.2.0.* An advanced repository address can include a password, for example
`rest:https://<user>:<password>@<host>/`. The panel encrypts it like the other backup credentials,
with the server's secrets key (`/var/lib/cloudground/secret.key`), and stores the address in its
database without the password. **Settings** and the backup list show the address masked. When you
upgrade from an earlier version, the panel encrypts any plaintext passwords it had stored the first
time it starts.

## Test the connection {#test}

Click **Test connection**. The test uses the saved settings, so it's only available when there are no
unsaved changes (*Save first: the test reads the saved settings*). If the repository responds, the
panel shows *Repository reachable* and how many snapshots it holds.

## Configure it from the command line {#cli}

```bash
cgctl settings set backup_s3_access_key '<access-key>'
cgctl settings set backup_s3_secret_key '<secret-key>'
cgctl settings set backup_s3_region '<region>'
cgctl settings set backup_password '<password>'
cgctl settings set backup_repository 's3:https://<endpoint>/<bucket>'
```

`backup_repository` takes the repository in the form shown in the table above. For Cloudflare R2, the
region is `auto`. Each command sets one key, so set the S3 keys before the repository: every time the
repository or the password changes, the panel tests the pair with whatever values are already saved.
On a server that already has a repository, a new repository is created with the saved password.
Changing `backup_password` on its own is refused, because the new password won't open the existing
repository. To start a new repository with a new password, save both fields together in
**Settings**.
