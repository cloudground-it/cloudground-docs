Every site keeps its backups in one restic repository. The data is encrypted on the server, with
the repository password, before it leaves.

## Choose the repository address {#repository-address}

The **Repository** field takes a restic address:

| Destination | Address form |
| --- | --- |
| S3-compatible object storage | `s3:https://<endpoint>/<bucket>[/<folder>]` |
| SFTP server | `sftp:<user>@<host>:/<path>` |
| REST server for restic | `rest:https://<host>/<path>` |
| Folder on this server | `/<path>` |

A folder on this server is not an off-site backup: if you lose the server, you lose the backups
too.

- **SFTP**: restic connects with `ssh` as root, with root's key and `known_hosts` (`/root/.ssh/`).
  Before saving, put root's public key on the remote server and connect once by hand as root to
  accept its host key: otherwise the test fails with `Host key verification failed`.
- **Backblaze B2**: use its S3-compatible endpoint (`s3:https://s3.<region>.backblazeb2.com/<bucket>`)
  with the keys in **S3 access key** and **S3 secret key**. A `b2:` address does not work: the panel
  passes restic only the S3 keys, and the test fails with `Account ID ($B2_ACCOUNT_ID) is empty`.

## Save the settings {#save}

1. Open **Settings** and find the **Off-site backups (restic)** panel.
2. Type the address in **Repository**.
3. Type the **Repository password**. Keep a copy of it outside this server: without the password
   the backups cannot be read.
4. For S3 object storage, fill in **S3 access key**, **S3 secret key** and **Region** (leave the
   region empty if the service does not ask for one).
5. Press **Save**.

When you change the repository or the password, the panel tries the pair before saving it. If the
repository does not exist yet, it is created. If it exists with another password, the panel
refuses to save: the existing backups would become unreadable.

## Test the connection {#test}

Press **Test connection**. If the repository answers, the panel shows *Repository reachable* and
the number of snapshots it holds.

## From the command line {#cli}

```bash
cgctl settings set backup_s3_access_key '<access-key>'
cgctl settings set backup_s3_secret_key '<secret-key>'
cgctl settings set backup_password '<password>'
cgctl settings set backup_repository 's3:https://<endpoint>/<bucket>'
```

Each command changes one key, so set the S3 keys before the repository: whenever the repository or
the password changes, the panel tries the pair with the values already saved. On a server that
already has a repository, a new repository is created with the saved password; `backup_password`
changed on its own is refused, because it does not open the previous repository. For a new
repository with a new password, save both fields together in **Settings**.
