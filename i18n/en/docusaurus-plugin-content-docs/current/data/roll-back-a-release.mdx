A rollback only changes which release serves the site. The releases are already on the server, so
the switch is instant. The database and uploaded files don't change: for those you need
a [restore](/docs/data/restore-a-backup).

## Go back to the previous release {#previous}

1. Open the site and go to the **Releases** tab.
2. Click **Instant rollback** and confirm.

The site switches back to the release that was live just before the current one. The current release
becomes *rolled back* and the previous one becomes *live*. If no earlier release has ever been live,
the panel refuses the rollback.

```bash
cgctl --wait rollback <site-id>
```

## Go back to a specific release {#specific}

Click **Activate** on the row of a *superseded* or *rolled back* release and confirm. Through the API:

```bash
curl --unix-socket /run/cloudground/api.sock -X POST \
  -H 'Content-Type: application/json' -H 'Authorization: Bearer <token>' \
  -d '{"deployment_id": <id>}' http://localhost/api/sites/<site-id>/rollback
```

You can only bring back a release that has been live before. A release that Safe Push rolled back for
making the site worse can't be activated again.

## Automatic rollback {#automatic}

After a Safe Push, Performance Guard measures production again. If the measured pages return a
different status code or errors, the panel switches back to the previous release on its own and marks
the new one as regressed. If the automatic rollback fails, the release stays *live* with the note
*Regressed after its promotion; the automatic rollback failed* and the panel raises an alert. In that
case, roll back by hand.
